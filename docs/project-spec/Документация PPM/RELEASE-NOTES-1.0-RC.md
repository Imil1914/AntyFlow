# Заметки о выпуске — PPM 1.0 RC (черновик)

Этот файл лежит рядом с [`CHANGELOG.md`](CHANGELOG.md) в той же папке документации выпуска: здесь — краткая
пользовательская сводка «что получил владелец», в CHANGELOG — подробная построчная история по датам. Текст ниже
рассчитан на нетехнического читателя: коротко, по делу, без внутреннего жаргона.

Раздел «Известные ограничения» специально написан так, чтобы его можно было почти без изменений перенести на
страницу справки `/about/ppm-guide` (короткие карточки «заголовок + одна строка», как остальные разделы этой
страницы). Саму страницу (`plane-fork/apps/web/app/(home)/about/ppm-guide/page.tsx`) правит не линия D — это код;
здесь только готовый текст. Сообщаю об этом отдельно и в ответе контроллеру.

## RC.3 (2026-09-29, ночь и день): единый вход, реальное время, коммиты в отчётах

**Главное.** Всё, что вы выбрали на ночь и день, сделано и проверено:

- **«Войти через PPM» на Git-сервере (G2.2).** Людей заводят только в PPM. На Git-сервере человек нажимает «Войти
  через PPM» — и сразу видит код своих проектов, без отдельного пароля. Доступ к коду следует за проектами: добавили
  в проект — видит код, убрали — доступ пропал за секунды, отключили — не войдёт ни в PPM, ни в Git. Руководитель
  проекта сам создаёт репозиторий на Git-сервере и подключает его в «Коде». Администраторы PPM — администраторы
  Git-сервера. Состояние синхронизации — в центре администратора, вкладка «Git-сервер».
- **Изменения видны всем сразу (UX2.1).** Если коллега меняет задачу, переносит её в спринт или направление, это за
  одну-две секунды видно у всех — в списках, на досках, в карточке задачи, на графиках спринта и в «Моих задачах»,
  без перезагрузки. Связь восстанавливается сама после обрыва и подтягивает пропущенное.
- **Коммиты в отчётах (G2.3).** В комментарии, описании задачи, странице и заметке Хранилища — кнопка «Вставить
  коммит/PR»: найти и вставить ссылку вида «PR #12 «Калибровка» · Слит 28 сент.» за три действия. На страницах и в
  заметках — «Что сделано за период»: готовая сводка за неделю (задачи, сменившие статус, их коммиты и PR).
- **«Отключить» / «Включить» пользователя** в центре администратора: уволенный сотрудник больше не войдёт ни в PPM,
  ни на Git-сервер (раньше такой кнопки не было).
- **Мониторинг и оповещения:** сервер сам сообщает в Telegram и/или на почту, если PPM или Git-сервер упал, кончается
  место на диске, не прошёл или давно не делался бэкап, скоро истекает сертификат. Настройка — `RUNBOOK.md`, §14.
- **Дочищен русский:** уведомления, заявки, настройки пространства, редактор документов (меню «/», панели, ошибки
  загрузки); из меню настроек убрана «Оплата и тарифы» (у вас своя установка, оплаты нет).
- **«Код»:** у слитого PR — время слияния: «Слит 28 сент., 14:05», полная дата — при наведении.

**Проверено:** каждая часть прошла ревью (у входа, доступов и отключения — ревью безопасности, найденные дыры
закрыты: захват учётки Git-сервера по почте, перегрузка входа, возврат отключённого своим же запросом); сквозная
проверка единого входа на живом Git-сервере Forgejo 15 — 9 сценариев из 9 (секреты не найдены ни в 27 тыс. строк
журналов, ни в ответах); итоговая проверка RC.3 — у второго участника изменения видны за 0,7 с, 20 одновременных пользователей и 200
изменений подряд — всё доставлено, в среднем за 0,15 с; сводка «Что сделано» совпала с базой; отключённый человек
теряет доступ к PPM и Git за 3 секунды; найденные мелочи исправлены. Тесты: API 1728, web 2138, скрипты
развёртывания 362 + 48 + 35.

**Известные ограничения RC.3:**

- Статус коммита или PR в отчёте — снимок на момент вставки (так и задумано для отчётов), сам не обновляется.
- Локальные учётки Git-сервера, заведённые вручную до единого входа, PPM не трогает — их пересматривает администратор
  (`RUNBOOK.md`, §17.14).
- «Отключить» не удаляет ключи API человека и не закрывает уже открытую вкладку документа — что делать, написано в
  `RUNBOOK.md`, §6.
- Запись в Git из PPM (ветка и черновой PR) для Forgejo по-прежнему не делается.

**Перед выкладкой RC.3 дополнительно к RC.2:** включить единый вход — `ppm-env.sh add-sso`, `up`, `git-bootstrap`
(`RUNBOOK.md`, §17.14); для оповещений — бот Telegram и/или почта и строка cron (§14).

## RC.2 (2026-09-29): собственный Git-сервер и правки по вашим просьбам

**Главное.** Рядом с PPM теперь работает собственный Git-сервер **Forgejo** на адресе `git.<ваш домен>` — код команд
хранится на вашем сервере, а не на GitHub. Разработчики работают обычным `git`: `clone`, `commit`, `push`, запросы на
слияние (PR) — в веб-интерфейсе Forgejo, он похож на GitHub. PPM видит репозитории проектов, коммиты и PR, сам
связывает их с задачами по номеру в сообщении коммита (`ROBOT-12: …`), ищет по коду и показывает Git-карточки на
Холсте. Администраторы Forgejo видят и скачивают код любой команды. PPM и Forgejo выкладываются на сервер вместе,
бэкапы и восстановление включают оба.

**Как это устроено для людей:**

- **Подключить репозиторий к проекту PPM** может глобальный администратор PPM: «Код» → «Подключить с нашего
  Git-сервера». Остальные видят подсказку, что это делает администратор.
- **Как скачать код** — у каждого репозитория в «Коде» есть готовые команды `git clone` по HTTPS и SSH с кнопкой
  «Копировать».
- **Статус PR** («Открыт», «Черновик», «Закрыт», «Слит») виден прямо в «Коде».
- **Люди и доступы к коду** в этом выпуске заводятся в самом Forgejo (объём «Быстрый»): администратор создаёт учётки,
  организации и команды по инструкции `RUNBOOK.md`, раздел 17. Единый вход через PPM и автоматические доступы по
  проектам — следующий шаг (G2.2).

**Что сделано по вашим просьбам:**

- **Вход:** если почта не найдена, PPM больше не предлагает молча «создать аккаунт», а честно говорит «Аккаунт с такой
  почтой не найден»; все сообщения при входе — по-русски (и во входе администратора, и на публичных страницах);
  в поле пароля — подсказки «Включён Caps Lock», «русская раскладка», «пробел в начале или в конце»; то же при смене
  пароля в профиле и при первой настройке.
- **Русский интерфейс:** диалоги подтверждения с правильными падежами («Удалить задачу BIO-4?»), даты по-русски
  («22 сент. – 1 окт. 2026»), календарь с понедельника, приоритеты («Срочный», «Высокий»…), подписи и подсказки
  свойств задач, окно создания и редактирования задачи, фильтры и «Вид», спринты, направления, документы,
  настройки и «Настроить навигацию».
- **Спринт с пересекающимися датами:** PPM сразу под выбором дат пишет, с каким спринтом пересечение и какие даты
  выбрать, — а не английскую ошибку после сохранения.
- **Выделение нескольких задач** в видах «Список» и «Таблица» и панель «Выбрано: N»: «Статус», «Исполнитель»,
  «Спринт», «Удалить». Удаление — как у одной задачи (история, уведомления, права автора или администратора);
  подтверждение показывает и подзадачи, которые уйдут вместе с родителем; фокус — на «Отмена».
- **Графики спринта и направлений обновляются сами** — после ваших изменений, при возврате на вкладку и раз в
  30 секунд; «Выгорание задач» больше не рисует ноль на будущих днях.
- **Холст:** исполнители в карточке задачи — аватарками, выбор — выпадающим списком (раньше открытый системный
  список налезал на карточку).

**Проверено:** сквозная проверка на отдельном стенде из собранных образов — 67 шагов из 70 с первого прохода (от
`git push` до коммита у задачи за считанные секунды, PR, пропущенное событие, поиск по коду, бэкап → восстановление,
вход, массовые действия, графики, Холст); найденные мелочи исправлены и перепроверены. Тесты: web 1504, API 607,
скрипты развёртывания 234.

**Известные ограничения RC.2 (Git-сервер):**

- Учётки и доступы к коду — вручную в Forgejo; единого входа через PPM пока нет (G2.2).
- Подключать репозитории Forgejo к проектам может только глобальный администратор PPM.
- В «Коде» у PR виден статус, но пока не дата слияния.
- Ссылки на коммиты в отчётах — обычными ссылками; кнопка «Вставить коммит/PR» и сводка «что сделано за неделю» —
  следующий шаг (G2.3).
- Изменения других участников в графиках видны с задержкой до 30 секунд; полное «реальное время» для всех —
  следующий шаг (UX2.1).
- Запись в Git из PPM (ветка и черновой PR) для Forgejo не делается; автосборки (Forgejo Actions) выключены.
- Переименованный репозиторий нужно заново подключить в «Коде» (история сохраняется).

**Перед выкладкой RC.2 дополнительно к списку ниже:** DNS-запись `git.<домен>` на тот же IP; порт `2222`, если нужен git
по SSH; первичная настройка Git-сервера и учётка администратора Forgejo для вас — по `RUNBOOK.md`, раздел 17.

## Что входит в PPM 1.0 RC

По каждому пункту в скобках — карточка-источник (полная история — в CHANGELOG и в самой карточке).

- **Свой продукт, не чужой Plane.** Отдельные название, цвета, шрифты и логотип; страница «О программе» с версией,
  сборкой и лицензией (I0.1, I0.2).
- **Всё по-русски, один вход.** Регистрация, меню, ошибки и подсказки — на русском по умолчанию; один логин на всё
  приложение, без второго пароля для Холста (I0.3, UX0.1, UX0.2, UX1.1).
- **Новый облик системы.** Спокойная цветовая тема (тёмная и светлая), читаемый шрифт, «Удобная»/«Компактная»
  плотность строк, доступность (контраст, фокус, клавиатура) — на «Задачах» и на Холсте (UX1.1, UX0.2).
- **Холст проекта («Мозг проекта»).** Общая доска команды с несколькими вкладками-досками на проект; заметки
  (с Markdown и формулами), документы, списки-задачи, таблицы, код, схемы и 10 фигур для блок-схем, стикеры,
  карточки задач и файлов, смысловые связи между объектами — всё сохраняется и переживает перезагрузку страницы
  (AF0.1–AF0.5, AF2.1).
- **Файлы и Хранилище.** Папки и Markdown-заметки со ссылками `[[между собой]]`, PDF и изображения с превью,
  версии и корзина, экспорт в ZIP (открывается в Obsidian и подобных программах) (I0.7, I1.1).
- **Задачи, Kanban и спринты.** Карточки задач и доска Kanban на Холсте всегда смотрят в одни и те же задачи Plane
  — без второй базы задач; обзор проекта, CSV-выгрузка и Markdown-сводка для руководителя (AF0.4).
- **«Живая карта проекта».** Кнопка «Собрать карту» строит доску по текущему спринту с разделами по направлениям,
  «светофором» просроченных и заблокированных задач, лотком «Не на карте» и панелью «Что изменилось с …» — на
  своей отдельной доске, старые доски не трогает (AF2.2).
- **Поиск по проекту.** «Мозг проекта» ищет по задачам, заметкам и PDF и всегда показывает, откуда взят ответ
  (ссылка на источник); без ИИ-модели и без внешних запросов (I0.8). Найденные и подтверждённые связи между
  объектами дополнительно поднимают релевантные источники и показывают «соседей» выбранной карточки (I1.2).
- **Git одним нажатием.** Раздел «Код»: подключение репозитория, ручные и (для GitHub) автоматические ссылки веток,
  коммитов и PR к задаче; карточки репозитория и PR на Холсте; поиск по коду с ссылкой на файл, коммит и строки
  (G0.1, G1.1, G1.2). Создание ветки и чернового PR прямо из PPM — после предпросмотра и подтверждения — реализовано,
  но по умолчанию выключено (подробности — в разделе «Известные ограничения»); (G1.3).
- **Защищённое администрирование.** Отдельный, заметный режим администратора для владельца платформы — с аудитом
  всех входов в чужие проекты; руководитель проекта видит только свои проекты (ADM0.1, AF0.1).

Подробный построчный список — что перенесено с desktop-версии AntyFlow, а что осталось открытым вопросом — в
матрице 21 (раздел «RC-статус» после сверки, см. ниже).

## Что нового именно в этом RC (сверх перечисленного выше)

- **Авто-слияние совместной работы на Холсте.** Правки разных объектов доски сливаются автоматически и незаметно —
  доска больше не уходит в режим «только чтение» только потому, что кто-то ещё сохранил доску. Если два человека в
  одну секунду правят одно и то же поле одного и того же объекта (например, оба меняют текст одной заметки),
  проигравшая правка не стирается: она сохраняется рядом копией с пометкой «Конфликтная копия» и заметным
  уведомлением. Если один двигает объект, а другой в это же время правит его текст — сохраняются обе правки. При
  потере связи и восстановлении доска сама аккуратно предлагает вашу несохранённую правку на новой копии страницы,
  без ручного восстановления из черновика. Включено по умолчанию (флаг `PPM_CANVAS_AUTOMERGE`); нюансы — в разделе
  «Известные ограничения» (задача RC-2).
- **Более понятная панель Холста.** По вашей же обратной связи о рейке инструментов: смысловая связь между
  объектами теперь ставится прямо на обычной стрелке — через «Смысл» на панели стрелки (кнопку «Смысловые связи»
  убрали), список смысловых связей доски переехал в панель «Доска»; у кнопки «Из проекта» — понятная иконка и
  подсказка; подсказки появились у всех кнопок рейки; у кнопок с подменю — стрелочка-раскрытие прямо на кнопке.
- **Создание ветки и чернового pull request прямо из PPM.** Два отдельных подтверждения: сначала предпросмотр и
  подтверждение ветки, затем (после того как в неё что-то закоммичено) — предпросмотр и подтверждение чернового
  PR; ничего не создаётся в GitHub без вашего подтверждения на каждом шаге, слияние (merge) PPM не делает никогда.
  Само создание по умолчанию **выключено** (`PPM_GIT_WRITE_ENABLED=0`, подробности — в «Известных ограничениях»):
  пока это так, PPM показывает готовые команды для терминала (`git fetch origin`, `git switch -c <ветка> <SHA
  основы>`, `git push -u origin <ветка>`) с кнопкой «Скопировать команды» — имя ветки проверяется и экранируется,
  поэтому эти команды безопасно вставлять в PowerShell или cmd, даже если название задачи содержит необычные
  символы.
- **Исправлено: сохранение исполнителя задачи.** Назначение исполнителя иногда отвечало ошибкой сервера (правка при
  этом сохранялась, но не попадала в историю активности) — починено; освобождённые/удалённые исполнители больше не
  показываются в карточках, фильтрах, CSV и поиске «Мозг проекта».
- **Исправлено: карточка задачи на Холсте принимала только одну правку подряд.** После первого быстрого изменения
  статуса/поля прямо на карточке второе бралось «в никуда» — карточка молча откатывала выбор. Теперь такого нет:
  повторные изменения сохраняются одно за другим.
- **Хранилище на S3 снова читает файлы.** Предпросмотр, индексация PDF для поиска и ZIP-экспорт Хранилища на
  серверах с S3-хранилищем (не локальный диск) — были сломаны (пустой предпросмотр, зависание индексации), теперь
  работают.
- **Шифрованные резервные копии.** Каждая резервная копия (база данных + файлы Хранилища) теперь шифруется
  (GPG, AES-256) отдельной парольной фразой, которая создаётся один раз и лежит отдельно от копии; переносить копию
  на другое хранение теперь безопасно, даже если его читает посторонний.
- **Готовый комплект для развёртывания и инструкция (RUNBOOK).** Полный набор для запуска PPM на боевом сервере
  (образы с зафиксированными версиями, HTTPS через обратный прокси, все нужные маршруты включая совместную работу
  на Холсте, проверки здоровья сервисов) плюс пошаговая инструкция по установке, резервному копированию,
  восстановлению и откату — всё уже проверено локально «в сухую» (чистый запуск, бэкап → восстановление, откат
  версии и возврат обратно).

## Известные ограничения

Коротко и честно — что уже не работает так, как хотелось бы, и почему это не страшно для первого выпуска.

- **Правки при закрытом браузере.** Несохранённые правки хранятся в браузере до следующего открытия доски; фоновой
  синхронизации через Service Worker пока нет.
- **Одновременная правка одного и того же поля одного объекта.** Копией-«двойником» сохраняется только проигравшая
  правка **своих** объектов доски (заметка, документ, список, таблица, код, рамка/группа и т. п.). У стрелок и у
  карточек-проекций (задача, файл, документ, Git-объект — их содержимое живёт не в самой доске, а в «Задачах»,
  Хранилище или Git) копии не делается: при столкновении остаётся уже сохранённая версия коллеги, а не обе. Это не
  расходится с «ничего не пропадает» — источник этих объектов (сама задача, файл, Git-объект) не в доске и не
  теряется никогда; на самой доске может смениться только раскладка/ссылка.
- **Отмена (⌘Z/Ctrl+Z) откатывает весь объект целиком.** Если вы отменяете свою правку объекта, а коллега уже
  успел его изменить после вас, отмена откатит и правку коллеги — «Отменить» действует на объект, а не на отдельно
  ваш кусок правки.
- **Автосохранение ждёт, пока вы допечатаете, без ограничения по времени.** Если вы прямо сейчас редактируете
  текст объекта, который параллельно изменил коллега, PPM не прерывает вас и не подставляет чужую версию под
  курсор — сохранение вашей правки просто откладывается до того, как вы закончите редактировать (независимо от
  того, сколько это займёт). Черновик всё это время держится в браузере; если браузер не даёт что-то сохранить
  (приватный режим, отключённое хранилище), черновик держится только в памяти вкладки и пропадёт при её закрытии.
- **При обрыве связи доска перезагружается сама.** Ваша несохранённая правка не теряется (переносится на новую
  копию страницы и досылается тем же действием), но камера, выделение и открытые панели сбрасываются — так ведёт
  себя используемая оболочка Plane при переподключении; в одном из следующих выпусков это станет плавнее.
- **Текст, набранный в заметке до того, как она успела полностью открыться, может потеряться.** Редкий случай —
  открыли только что созданную заметку и сразу начали печатать ещё до её полной загрузки.
- **Импорт настоящих desktop-досок (.flow.json).** Формулы и вложения таких досок импортируются как заглушки;
  исходный файл при этом не теряется.
- **Ручной аудит с экранным диктором и реальными телефонами.** Автоматически проверено (Axe, WCAG A/AA) и с
  клавиатуры; ручная проверка со скринридером и на реальных мобильных устройствах — в одном из следующих выпусков.
- **Мониторинг.** Автоматические метрики, трейсы и алерты не входят в этот выпуск; работоспособность проверяется
  вручную по инструкции (runbook); для команды из 5–20 человек это ожидаемый режим.
- **Объём базы данных.** Каждое сохранение доски хранится отдельной версией без автоматического сжатия старых
  версий (рассчитано на небольшие команды; объём базы контролируется по инструкции эксплуатации).
- **Второй Git-провайдер и свой Git-сервер.** Пока подключается только GitHub; автоматическое слияние pull request
  (merge) PPM не делает — это всегда действие человека в GitHub.
- **ИИ-помощник и ИИ-агенты.** Сознательно не входят в PPM 1.0 (решение владельца); интерфейс скрыт флагами.
- **Webhook на уровне приложения GitHub.** Пока работает webhook конкретного репозитория (проверено вживую);
  общий webhook на уровне приложения для будущих, ещё не подключённых репозиториев — следующий шаг.
- **Вкладки открытых досок не синхронизируются между устройствами.** Это настройка браузера на конкретном
  компьютере, а не общая настройка проекта.
- **Создание веток и pull request прямо из PPM выключено по умолчанию.** Предпросмотр, два подтверждения и аудит
  полностью готовы и проверены (в т. ч. на подставном GitHub), но живой проверки на настоящем репозитории ещё не
  было — поэтому включение (`PPM_GIT_WRITE_ENABLED=1`) остаётся решением владельца **после** такой проверки. Пока
  выключено: ветку и черновой PR создаёте вручную в GitHub (PPM покажет готовые команды, см. «Что нового»), а PPM
  подхватит их по уже работающему webhook.
- **Экспорт из Хранилища и создание нового bucket на S3.** У этих двух путей (в отличие от обычного чтения/записи
  файлов) ещё нет новых сетевых тайм-аутов — при неполадках сети операция может ждать дольше, чем должна бы.
- **Строгая политика безопасности контента (CSP) браузера.** Пока не включена; запланирована на один из выпусков
  после этого RC.
- **Комментарии и реакции на объектах доски.** Отложены на следующий выпуск (проект «Холст 2.0», этап П3);
  сейчас можно обсуждать задачи только в разделе «Задачи».
- **Ограничения «Инструментов Холста» (AF2.1).** До 10 000 знаков форматированного текста в заметке — длиннее
  показывается простым текстом с пояснением; кнопка «+» у повёрнутой фигуры схемы считается по её обычной
  прямоугольной (габаритной) рамке; до кнопки «+» нельзя дойти клавишей Tab; если два человека одновременно переносят картинки
  одной доски в Хранилище, может остаться один лишний файл; повторный перенос картинки после отмены (⌘Z) в новой
  вкладке может создать копию файла; предпросмотр Word/Excel/PowerPoint не имеет отдельного тайм-аута (ограничен
  размером файла, худший измеренный случай — 1,7 секунды); два способа создания документа («Сделать документом» и
  «Документ») пока не объединены в один — это технический долг, не потеря данных.
- **Ограничения «Живой карты проекта» (AF2.2).** Живых обновлений по WebSocket, автоматической перестройки карты,
  нескольких спринтов на одной карте, графиков сгорания и комментариев пока нет (комментарии — см. выше, П3);
  «Отменить» сразу после «+ Добавить» может визуально наложить карточку на соседнюю секцию; связь между соседними
  карточками одной секции показывается коротким штрихом без подписи; «Светофор» для задач вне спринта карты
  использует последние 1000 изменённых задач проекта с обновлением не чаще раза в 5 минут — в очень больших и
  давно неактивных проектах пометка «заблокирована» может не появиться; доски, сохранённые до этого выпуска, не
  показывают как «изменено» правки, сделанные раньше первого сохранения самой доски (ограничение снимается само
  через 30 дней); PR, впервые увиденный уже закрытым без слияния, в ленте показывается как «открыт» (так было и
  раньше); скрытые вкладки досок раз в 30 секунд перечитывают привязки задач.

## Решения владельца перед тем, как открыть доступ кому-то ещё

Это короткий чек-лист именно того, что нужно решить или сделать один раз, перед тем как PPM увидит кто-то за
пределами вас/команды исполнителей. Он не про качество RC — он про юридические и учётные вещи, которые не
проверяются автоматически.

1. **Публикация изменённого исходного кода (AGPL, §13).** PPM и Plane внутри него — на лицензии AGPL-3.0-only:
   если этот сервер станет доступен по сети кому-то ещё, тем людям нужно предложить доступ к исходному коду именно
   этой версии (не только к оригинальному Plane). Технически страница «О программе» уже готова это показать —
   решение о самой публикации (и о том, куда именно её выложить) остаётся за вами.
2. **Условия tldraw SDK.** Холст использует tldraw без коммерческой лицензии — значит, надпись «Made with tldraw»
   на Холсте должна оставаться видимой. Если для вас это неприемлемо, нужна отдельная коммерческая лицензия tldraw
   ещё до открытия доступа.
3. **Стать администратором при первом запуске.** Публичная самостоятельная регистрация выключена; первого
   администратора инстанса создаёте вы сами отдельной защищённой командой (пароль вводите только вы, нигде не
   сохраняется). Это нужно сделать один раз при разворачивании, до приглашения кого-либо ещё.
4. **Держать самостоятельную регистрацию выключенной**, если только вы осознанно не решите иначе, — по умолчанию
   новые люди могут попасть в PPM только по приглашению, не через публичную форму регистрации.
5. **Хранить парольную фразу резервных копий отдельно от самих копий.** Она создаётся один раз при настройке
   сервера; без неё восстановить копию не получится, поэтому её стоит сохранить в отдельном надёжном месте (не в
   той же папке, что бэкапы).
6. **Не включать создание веток/PR из PPM (`PPM_GIT_WRITE_ENABLED`), пока не пройдёте живую проверку** на реальном
   репозитории GitHub — до этого функция сознательно выключена (см. «Известные ограничения»).
