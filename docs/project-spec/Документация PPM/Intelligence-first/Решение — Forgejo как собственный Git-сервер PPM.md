# Решение — Forgejo как собственный Git-сервер PPM

## Статус

`approved`: 2026-09-28 владелец выбрал Forgejo (не GitLab CE) и объём «Быстрый»; PPM и Forgejo выкладываются на
сервер вместе. Карточка реализации — G2.1. Единый вход и автодоступы — G2.2, ссылки на коммиты в отчётах — G2.3.

## Контекст

Замысел владельца (2026-09-28): команды пишут код и делают `git push`/`pull` и запросы на слияние на **наш** сервер,
PPM собирает весь код проектов, администраторы видят и скачивают код любой команды, а в отчётах о работе можно
ссылаться на коммиты — «как GitLab, установленный у себя».

Состояние PPM на 2026-09-28 (проверено по коду):
- единственный провайдер — GitHub App (`plane-fork/apps/api/plane/ppm_git/providers/github.py`);
  `providers/base.py` содержит только классы ошибок, а семь модулей обращаются к `GitHubAppClient` напрямую;
- есть: автосвязь коммит/PR/ветка ↔ задача по ключу (`provider_services.auto_link_git_object`), Git-карточки на
  Холсте, индексация кода для поиска («Мозг»), доступ глобального администратора PPM к Git любого проекта;
- нет: другого провайдера, собственного Git-сервера, просмотра файлов/diff/ревью PR внутри PPM.

Архитектурный принцип G2.1 сохраняется: PPM **подключает** Git-сервер, а не реализует его сам.

## Решение

1. **Сервер — Forgejo** (свободный форк Gitea, лицензия GPLv3+ с v9.0), ветка с долгой поддержкой **15.x LTS**
   (поддержка до 2027-07-15), официальный образ `codeberg.org/forgejo/forgejo:15-rootless`, закреплённый по digest.
   Используется без изменений; на сервере не распространяется — обязательств по публикации исходников нет.
2. **Размещение** — на том же сервере в комплекте `plane-fork/deployments/ppm`, отдельным хостом
   `git.<домен PPM>` (отдельный origin: код и разметка Forgejo не исполняются в origin PPM). HTTPS — через тот же
   Caddy (ACME / `tls internal`), git по SSH — встроенный SSH-сервер Forgejo на порту `2222` (можно выключить).
   База — отдельная база `forgejo` с отдельной ролью в том же PostgreSQL; данные репозиториев — отдельный том.
3. **Объём «Быстрый» (G2.1).** В Forgejo свои учётные записи: людей, организации, команды и доступы заводит
   администратор в Forgejo. Открытой регистрации нет, без входа ничего не видно. PPM не управляет доступами к коду.
4. **Связка с PPM** — второй провайдер `forgejo` через общий провайдерный контракт `ppm_git` (выделяется из GitHub):
   репозитории, ветки, коммиты, PR, индексация кода, автосвязь с задачами — те же модели и тот же интерфейс, что у GitHub.
   - PPM читает Forgejo служебной учётной записью `ppm-bot` (администратор Forgejo), токен **только на чтение**
     (`read:repository,read:organization,read:user`), хранится только в окружении сервера.
   - События — один **системный вебхук** Forgejo (все репозитории) на внутренний адрес API PPM, подпись
     `X-Forgejo-Signature` (HMAC-SHA256), повтор по `X-Forgejo-Delivery` не меняет данные дважды. Вебхук и токен
     создаёт скрипт развёртывания; у PPM нет прав писать в Forgejo.
   - Подключать и отключать репозитории Forgejo к проекту может **только глобальный администратор PPM**: служебная
     учётная запись видит весь код, поэтому выбор репозитория не должен давать РП доступ к чужому коду. В G2.2, когда
     появится единый вход, право перейдёт к РП с проверкой его доступа в Forgejo.
5. **Просмотр кода, diff, ревью и слияние PR** — в веб-интерфейсе Forgejo. PPM показывает метаданные и ведёт туда
   ссылками; собственный просмотрщик кода в PPM не делается.
6. **Запись в Git из PPM** (ветка и черновой PR, G1.3) для Forgejo не делается в G2.1; флаг `PPM_GIT_WRITE_ENABLED`
   по-прежнему выключен по умолчанию.
7. **Резервные копии** Forgejo (дамп базы `forgejo` и том данных) входят в тот же зашифрованный архив
   `ppm-backup.sh`; восстановление и учения — в `ppm-restore.sh` и RUNBOOK.

## Почему Forgejo, а не GitLab CE

| Критерий | Forgejo 15 LTS | GitLab CE |
|---|---|---|
| Память для небольшой команды | ~0,5–1 ГБ | от 8 ГБ только на GitLab |
| Обслуживание | один контейнер, настройки переменными окружения | много сервисов, тяжёлые обновления |
| Репозитории, PR, ревью, права, вебхуки, API | есть | есть |
| CI/CD | Forgejo Actions (в G2.1 выключено) | сильнее |
| Лицензия | GPLv3+ (свободная) | MIT (CE) |
| Интерфейс | похож на GitHub | свой |

Для объёма PPM (команды до десятков человек, код + связь с задачами) Forgejo даёт нужное при в разы меньших ресурсах.

## Альтернативы

1. **GitLab CE** — отклонено владельцем 2026-09-28 (ресурсы и эксплуатация, см. таблицу).
2. **Только GitHub** — отклонено: код должен храниться на своём сервере.
3. **Git-сервер внутри PPM** — отклонено архитектурой (G2.1 «Не входит»).
4. **Единый вход сразу** (PPM как OpenID Connect-провайдер для Forgejo + автодоступы по проектам) — отложено
   владельцем в G2.2 ради срока; технически проверено: Forgejo умеет вход через внешний OpenID Connect с
   автосозданием учёток и группами, `django-oauth-toolkit` 3.4 (Django 5.2) умеет роль провайдера.
5. **Forgejo как вход для PPM** (готовый в Plane «Войти через Gitea») — отклонено: центр учёток ушёл бы из PPM, а
   токены Forgejo без областей (полные права пользователя) хранились бы в базе PPM.

## Последствия

- Сервер к выкладке: 4 ядра, 8 ГБ памяти, от 100 ГБ диска; DNS-запись `git.<домен>` на тот же IP; порт `2222`, если
  нужен git по SSH.
- Владелец становится администратором Forgejo (первая учётка создаётся скриптом, пароль меняется при первом входе);
  людей и доступы к коду заводит в Forgejo по инструкции RUNBOOK.
- Существующие проекты с GitHub можно перенести встроенной миграцией Forgejo или оставить на GitHub — PPM работает с
  обоими провайдерами одновременно.
- Смена провайдера у проекта — отдельное действие: отключение репозитория сохраняет историю и ссылки G0.1.

## Откат

Выключить провайдер Forgejo в PPM (пустые `PPM_FORGEJO_*`): подключения Forgejo помечаются недоступными, история,
ссылки и карточки остаются. Сервис Forgejo можно остановить, не трогая PPM; данные Forgejo сохраняются в томе и в
резервных копиях. Удаление данных Forgejo — только отдельным подтверждённым действием владельца.
