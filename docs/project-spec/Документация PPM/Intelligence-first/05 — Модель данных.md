# 05 — Модель данных

Поля и таблицы AI/agent-контуров ниже фиксируют совместимость с уже созданными
записями. Их расширение и приёмка исключены из плана PPM 1.0; удаление схемы
или пользовательских данных этим решением не предусмотрено.

## Общие соглашения

- первичные ключи PPM: UUID;
- ссылки на Plane хранят UUID Plane без локальной копии сущности;
- все project-scoped таблицы содержат `workspace_id` и `project_id`;
- `created_by`/`updated_by` — Plane user UUID;
- timestamps — UTC в базе, локализуются в UI;
- удаление по умолчанию мягкое только там, где нужна история;
- secrets не хранятся в обычных таблицах;
- JSON-поля имеют `schema_version` и Zod/serializer validation;
- derived records содержат `source_version` или `content_hash`.

## Глобальное администрирование PPM

### `ppm_global_admins`

Защищённая platform role, не связанная с приглашением в workspace/project.

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | UUID | PK |
| `user_id` | UUID | unique active, Plane user |
| `status` | enum | `active/revoked` |
| `granted_by` | UUID nullable | bootstrap либо действующий global admin |
| `reason` | varchar | обязательное audit-пояснение |
| `created_at`, `revoked_at` | timestamp | lifecycle |

Назначение и отзыв выполняются только через защищённый bootstrap/admin flow с повторной аутентификацией и audit.
Project/workspace invitation API никогда не пишет в эту таблицу.

## Canvas

### `ppm_project_canvases`

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | UUID | PK |
| `workspace_id` | UUID | Plane workspace |
| `project_id` | UUID | Plane project |
| `name` | varchar | default `Мозг проекта` |
| `status` | enum | `active/archive` |
| `default_board_id` | UUID nullable | FK после создания первой доски |
| `created_by` | UUID | Plane user |
| `created_at` | timestamp | required |
| `updated_at` | timestamp | required |

Unique active Canvas per `project_id` остаётся постоянным инвариантом. Множество рабочих областей реализуется
досками внутри Project Canvas, а не дополнительными Canvas проекта.

### `ppm_canvas_boards`

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | UUID | PK |
| `workspace_id` | UUID | Plane workspace |
| `project_id` | UUID | Plane project |
| `canvas_id` | UUID | FK |
| `name` | varchar | 1–120 |
| `position` | decimal/string rank | устойчивый порядок |
| `status` | enum | `active/archived` |
| `current_version` | integer | `>= 0` |
| `created_by`, `updated_by` | UUID | Plane users |
| `created_at`, `updated_at`, `archived_at` | timestamp | lifecycle |

Unique active normalized `(canvas_id, name)`; минимум одна активная доска на Canvas. Архивирование не удаляет
snapshots/history. `workspace_id` и `project_id` дублируются намеренно для deny-by-default фильтра и индексов.

### `ppm_canvas_versions`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | UUID | PK |
| `canvas_id` | UUID | FK |
| `board_id` | UUID | FK, required после migration |
| `version` | integer | монотонная версия |
| `snapshot_json` | JSONB/pointer | tldraw snapshot либо object key |
| `content_hash` | char(64) | SHA-256 canonical JSON |
| `created_by` | UUID | автор сохранения |
| `created_at` | timestamp | время |

Unique `(board_id, version)`. Версия не изменяется после создания. Существующие версии Canvas мигрируют на
автоматически созданную доску `Главная`; временный `canvas_id` сохраняется для проверки целостности и совместимости.

### `ppm_canvas_bindings`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | UUID | PK |
| `canvas_id` | UUID | FK |
| `board_id` | UUID | FK |
| `shape_id` | varchar | стабильный tldraw shape ID |
| `entity_type` | enum | `work_item/page/plane_attachment/vault_file/cycle/module/repository/branch/commit/pull_request/agent_run` |
| `entity_id` | varchar/UUID | ID источника |
| `source_version` | varchar nullable | optimistic cache version |

### `ppm_semantic_edges`

| Поле | Тип | Назначение |
|---|---|---|
| `id` | UUID | PK |
| `canvas_id` | UUID | FK |
| `board_id` | UUID | FK |
| `from_shape_id` | varchar | начало |
| `to_shape_id` | varchar | конец |
| `relation_type` | enum | `relates_to/depends_on/blocks/explains/implements/evidence_for/contradicts/derived_from/result_of` |
| `label` | varchar nullable | пользовательское пояснение |
| `confidence` | decimal nullable | только для AI proposal |
| `origin` | enum | `user/agent/import` |
| `confirmation_status` | enum | `proposed/confirmed/rejected` |
| `confirmed_by` | UUID nullable | проверивший proposal |
| `confirmed_at` | timestamp nullable | время проверки |
| `created_by` | UUID | автор |
| `created_at` | timestamp | время |

Графическая стрелка может существовать без semantic edge. Пользовательская/import-связь создаётся подтверждённой;
agent-связь всегда создаётся как `proposed` и не участвует в GraphRAG до явного подтверждения.

Unique edge scope включает `board_id`; связь между shape разных досок не создаётся неявно. Междосочная ссылка
оформляется отдельной link-node/binding с явным target board и проходит permission check при открытии.

Project-scoped подтверждённые решения и производные сводки.

| Поле | Тип | Назначение |
|---|---|---|
| `kind` | enum | `decision/daily_summary/weekly_summary/release_summary` |
| `title`, `body` | text | неизменяемое содержание записи |
| `origin` | enum | `user/agent` |
| `confirmation_status` | enum | `proposed/confirmed/rejected` |
| `freshness_status` | enum | `current/possibly_stale` |
| `content_hash` | char(64) | идемпотентность содержимого |
| `client_operation_id` | UUID | повторяемая операция пользователя |

### `ppm_project_memory_source_refs`

Каждая запись памяти имеет 1–50 ссылок на источники того же проекта. Ссылка хранит `knowledge_source`,
`source_type`, canonical `source_id`, снимок `source_version` и `locator_json`. Если текущая версия хотя бы одного
источника отличается от снимка либо источник более не готов, запись получает `possibly_stale`; текст записи не
переписывается молча.

## Git

### `ppm_git_connections`

Хранит provider type, installation/account metadata, secret reference, status и timestamps. Сам token/SSH private key в таблице не хранится.

### `ppm_repositories`

Provider repository ID, project scope, owner/name, default branch, clone URLs, visibility, sync cursor, last sync. Unique `(connection_id, provider_repository_id)`.

### `ppm_git_links`

Связь Plane Work Item или Canvas node с `branch/commit/pull_request/repository`. Provider object ID и canonical URL обязательны.

### `ppm_git_events`

Raw body не сохраняется бессрочно. Хранятся delivery ID, normalized event, payload hash, processing state, repository ID и timestamps. Unique `(connection_id, delivery_id)`.

## Миграционные правила

1. Каждая модель создаётся только migration-файлом.
2. PPM migrations не удаляют/переименовывают core Plane columns.
3. Backfill выполняется отдельной idempotent job.
4. Новая версия Canvas/agent JSON получает schema migration.
5. Индексные таблицы можно перестроить, но canonical Vault versions нельзя терять.
6. Down migration не используется как единственный rollback при потенциальной потере данных.
