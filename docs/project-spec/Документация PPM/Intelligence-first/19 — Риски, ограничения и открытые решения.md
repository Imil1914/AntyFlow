## Открытые решения

### O1. Название и логотип продукта

Нужны утверждённые wordmark, mark, favicon и правила использования. До решения допускается нейтральный `PPM` asset, но не случайный новый бренд.

### O2. Vector backend

Архитектура поддерживает abstraction. Предварительный выбор для простого контура: Postgres full-text + pgvector в PPM schema/database. До production подтвердить совместимость image/extensions и migration plan; альтернативный отдельный vector service вводится только по ADR.

### O3. Model providers

Нужно решить, какие OpenAI-compatible endpoints допускаются для demo/production, где хранятся secrets и разрешено ли отправлять project content внешнему provider.

### O4. Первый Git provider

Выбрать GitHub или GitLab для G1 исходя из реальных аккаунтов. Не реализовывать два adapter одновременно.

### O5. Self-hosted Git

Forgejo — кандидат G2. До реализации проверить лицензию, актуальный release, SSO/OAuth, Actions/LFS, backup и ресурсы. Решение не считается принятым только по упоминанию в ТЗ.

### O6. Pages vs Vault default

Текущая рекомендация: `Создать заметку` создаёт Vault Markdown, `Создать совместную страницу` создаёт Plane Page. Нужна пользовательская проверка терминов.

### O7. Realtime Canvas

Определить: переносить `@tldraw/sync`, использовать Plane live infrastructure или отдельный service. До решения MVP использует versioned autosave.

### O8. Physical database boundary

PPM Django apps могут использовать Plane Postgres в отдельной schema или отдельную PPM database. Для D0 допустима одна instance с изолированными таблицами; перед production оценить backup/upgrade boundary.

### O9. Code/Notebook runtime

Выбрать sandbox/runtime, quotas, network policy, artifact storage и cancel model для web-эквивалентов OpenCode,
terminal и Jupyter. До отдельного security ADR кодовая нода остаётся редактором/preview без исполнения.

### O10. Global admin operations

До production определить обязательные MFA/re-auth, break-glass recovery и dual-control policy. Базовый инвариант уже
принят: роль не выдаётся invitations/обычными role endpoints, а каждое пересечение project scope пишется в audit.

## Неопределённость текущего AntyFlow

- desktop code содержит полезные прототипы, но не является готовым web package;
- AnythingLLM workspace может пересекать доски — это неприемлемо для целевого tenant model;
- локальный PDF RAG изолирован по PDF, но не заменяет project-level index;
- local file watcher не работает как многопользовательская синхронизация;
- terminal/Jupyter/webview нельзя считать готовыми web-функциями.

## Решения, которые нельзя принимать молча

- смена pinned Plane release;
- включение коммерческого Plane component;
- хранение data у внешнего AI provider;
- автоматическое индексирование private code;
- создание/merge PR агентом;
- полная двусторонняя синхронизация Page↔Markdown;
- destructive migration Vault/Canvas;
- публичный запуск без source/legal review.
