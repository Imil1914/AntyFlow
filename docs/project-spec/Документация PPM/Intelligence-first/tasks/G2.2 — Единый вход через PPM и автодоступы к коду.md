# G2.2 — Единый вход через PPM и автодоступы к коду

## Пользовательский результат

Человека заводят только в PPM. На Git-сервере он входит кнопкой «Войти через PPM», а доступ к коду следует за
проектами PPM. Добавили в проект — видит код проекта, убрали — доступ пропал, отключили в PPM — не может войти и
в Git. Администраторы PPM — администраторы Git-сервера.

## Основание

Отложено владельцем 2026-09-28 из G2.1 ради срока (объём «Быстрый»). Технически проверено:
[Решение — Forgejo как собственный Git-сервер PPM](<../Решение — Forgejo как собственный Git-сервер PPM.md>),
альтернатива 4.

## Зависимости

- G2.1 accepted.

## Scope

- PPM как OpenID Connect-провайдер для одного доверенного клиента (Forgejo): код авторизации + PKCE, discovery,
  JWKS (RS256), userinfo; утверждения `sub`, `preferred_username`, `email`, `name`, `groups`. Библиотека
  `django-oauth-toolkit` 3.4+ (Django 5.2).
- Forgejo: источник входа OpenID Connect с автосозданием учёток, группа администраторов по `groups`, встроенная
  форма пароля выключена (аварийный администратор — через командную строку).
- Синхронизация прав из PPM в Forgejo служебным токеном: пространство → организация, проект → команда с доступом к
  репозиториям проекта, роль → уровень доступа, исключение из проекта → удаление из команды, отключение пользователя
  → запрет входа; сверка по расписанию исправляет расхождения.
- РП подключает репозитории Forgejo к своему проекту, если у него есть доступ к репозиторию в Forgejo.
- Статус Git-сервера и синхронизации в центре администратора.

## Не входит

- вход в PPM через Forgejo; внешний провайдер учёток (Keycloak, Authentik).

## Критерии приёмки

1. Новый участник проекта входит в Forgejo кнопкой «Войти через PPM» без отдельного пароля и сразу видит код
   проекта.
2. Исключение из проекта убирает доступ к коду, отключение пользователя — вход в Forgejo, в пределах одной сверки.
3. Токены и ключи подписи не попадают в браузер, логи и резервные копии в открытом виде.
