# I0.7 — Project Vault Markdown и PDF MVP

## Пользовательский результат

В каждом project есть изолированное файловое дерево. Пользователь создаёт папки и Markdown, загружает PDF, открывает материалы и выбирает, индексировать ли их в Project Brain.

## Зависимости

- I0.3;
- Vault/data/security документы 05/09/13;
- private object storage baseline.

## Scope

- Vault/entry/version models/migrations;
- idempotent Vault root project provisioning;
- folder CRUD без hard delete;
- Markdown create/read/versioned update;
- PDF upload/download/preview metadata;
- private object keys by UUID/version;
- index policy;
- tree UI на базе UX desktop Vault;
- permission, validation и path safety;
- minimal `vault_file_ref` selector/projection, если I0.5 доступен.

## Не входит

- DOCX/PPTX/XLSX extraction;
- full backlinks graph;
- realtime Markdown collaboration;
- filesystem/WebDAV sync;
- automatic Page↔Markdown sync;
- OCR;
- hard delete blob history.

## Порядок реализации

1. Зафиксировать переносимые UI-паттерны desktop Vault, не импортируя Electron API.
2. Добавить additive models/constraints.
3. Реализовать project permission service.
4. Реализовать tree/read/create.
5. Реализовать Markdown update с base version.
6. Реализовать upload initiate/complete с size/hash/MIME.
7. Добавить quarantine/status hook.
8. Реализовать signed download/preview.
9. Добавить index policy inherited state.
10. Добавить tree/editor/upload UI и all states.
11. Проверить rename/move stable ID, если вошло в доступный scope; иначе явно отложить без ложной кнопки.
12. Добавить Canvas projection после готовности binding.

## Критерии приёмки

1. Project получает один Vault.
2. Markdown сохраняется новой version и переживает restart.
3. Stale Markdown edit получает conflict.
4. PDF хранится private и открывается разрешённому участнику.
5. Storage key не содержит original path/name.
6. Outsider не получает tree/content/signed URL.
7. Invalid/oversized upload не публикует active entry.
8. Index policy видна пользователю.
9. Canvas projection не копирует blob.

## Проверки

- migrations/constraints;
- CRUD/version conflict;
- permission matrix;
- MIME/size/path/unicode cases;
- failed upload cleanup;
- signed URL expiry;
- restart E5/E6/E9;
- web/API build.

## Rollback

Выключить Vault flag. Metadata/blobs/versions сохраняются. Orphan multipart uploads чистятся безопасной job по возрасту; canonical blobs не удаляются rollback-ом.

## Stop rules

- предлагается использовать browser local filesystem как server source;
- object storage публичен;
- original path становится object key;
- overwrite не создаёт version;
- upload считается готовым до проверки metadata.

## Реализовано 2026-09-19

- добавлен отдельный backend-модуль `plane.ppm_vault` с project-scoped Vault, root entry, деревом папок, стабильными UUID и soft delete;
- сохранена совместимость с уже подготовленной схемой `ppm_vaults / ppm_vault_entries / ppm_vault_versions`; Markdown-содержимое добавлено отдельной additive migration `0002`;
- Markdown создаётся как version 1, каждое сохранение создаёт immutable version, stale `base_version` возвращает `409 VAULT_VERSION_CONFLICT`;
- PDF проверяется по размеру и сигнатуре до публикации active entry; приватный object key состоит только из UUID Vault/entry/version и расширения;
- local preview отдаётся авторизованным API через `FileResponse`, production S3 — через короткий signed URL (300 секунд) с private ACL;
- project permission matrix использует общий PPM boundary: руководитель/участник редактируют, viewer читает, outsider не получает tree/content/PDF, глобальный администратор сохраняет контролируемый доступ;
- реализованы tree UI, папки, Markdown editor/preview, PDF upload/preview, явная index policy и состояние «Только чтение»;
- «Хранилище» заменило старую заглушку «Знания» в маршруте проекта;
- материал Vault добавляется на активную доску Canvas как `vault_file_ref`; в snapshot сохраняются только UUID, имя, extension, version и source URL — blob/content не копируются;
- rename/index policy/soft delete доступны через API; move UI намеренно не показан и остаётся отдельным расширением после owner review.
