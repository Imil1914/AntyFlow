# I0.3 — PPM shell, русская локализация и первый вход

## Пользовательский результат

Пользователь регистрируется и работает в собственной оболочке PPM. На главном пути отсутствует визуальная идентичность Plane, русский язык включён по умолчанию, сохраняется один login.

## Зависимости

- I0.2;
- навигация и термины из документов 02/11/18.

## Scope

- auth/invitation/workspace/project first path;
- default locale `ru` для нового пользователя с возможностью `en`;
- PPM global/project shell;
- новая project navigation;
- routes-placeholder `Мозг проекта`, `Знания`, `Код` с feature states;
- PPM empty/loading/error states основного пути;
- command palette/nav accessibility;
- link `Открытый исходный код`;
- user-facing brand audit allowlist.

## Не входит

- полная перерисовка settings/admin/emails;
- реализация Canvas/Vault/Git content;
- изменение Plane auth model.

## Порядок реализации

1. Зафиксировать E1 screenshots baseline.
2. Определить route map без изменения canonical project IDs.
3. Создать shell wrapper/layout.
4. Подключить русские labels через i18n keys.
5. Настроить default locale only for users without saved language.
6. Переработать auth/onboarding/project create surfaces.
7. Добавить navigation и feature placeholders.
8. Проверить deep links и browser refresh.
9. Проверить viewer/member/admin variants.
10. Выполнить automated brand scan + visual E1.

## Критерии приёмки

1. Нет второго login/token store.
2. Новый пользователь по умолчанию видит русский UI.
3. Смена языка сохраняется.
4. Основная navigation соответствует документу 02.
5. Auth, home, project, Work Items не показывают Plane brand вне legal allowlist.
6. Direct link/reload не теряет context.
7. Отключённые функции объясняют следующий этап, а не падают.
8. Штатный Work Item flow работает.

## Проверки

- auth/project E2E;
- locale persistence;
- navigation capability tests;
- visual Graphite/Light;
- keyboard/focus;
- brand string/assets scan;
- Plane baseline regression.

## Текущее состояние реализации

Локально реализованы feature-gated PPM shell, русский язык по умолчанию для нового профиля, новая навигация проекта, reload-safe routes и поясняющие состояния для будущих разделов. Auth, onboarding, invitation, home, project navigation, Work Item flow и maintenance first path переведены на PPM brand. Добавлен автоматический brand audit с контролируемым legal allowlist.

Пройдены проверки:

- `@ppm/brand`: 18 unit-тестов, typecheck, build и audit 23 пользовательских поверхностей;
- `web` navigation capabilities: 8 unit-тестов для Guest/Viewer, Member и Admin, project feature switches, rollback-режима, доступной project navigation и command search;
- `web`: route typegen, typecheck, lint изменённых поверхностей без ошибок и предупреждений, production build;
- rollback build с `PPM_BRAND_ENABLED=0` и `PPM_SHELL_ENABLED=0`;
- ручной smoke auth/brand foundation/direct project link в Graphite и Light;
- чистая гидратация `/` и `/about/brand-foundation` в headless Chrome без React hydration errors;
- штатный `serve -s build/client` возвращает `200 text/html` для `/` и прямого `/about/brand-foundation`;
- direct project link после reload сохраняется в `next_path` до авторизации;
- обе project-navigation реализации имеют локализованный `nav` landmark, `aria-current`, видимый focus-ring и именованные overflow actions; невидимые измерительные ссылки исключены из Tab-порядка;
- command search локализован, размечен как связанный со списком `combobox`, показывает focus state и предоставляет имя кнопке очистки;
- production maintenance state отображается как PPM на русском языке.
- на локальном API пройден полный first path: создание аккаунта, один login, профиль, workspace и автоматически созданный project;
- новый профиль получил `ru`, переключение `ru → en → ru` сохранилось после reload и в профиле API;
- создан, открыт прямой ссылкой, изменён и сохранён реальный Work Item; после reload сохранились URL, project context и русские PPM labels;
- на авторизованных данных проверена фактическая навигация Guest/Viewer, Member и Admin; для Guest отдельно подтверждён серверный `403` на изменение project settings, после проверки роль возвращена Admin;
- routes `Обзор`, `Мозг проекта`, `Знания` и `Код` открываются прямой ссылкой и после reload, а planned-разделы объясняют следующий этап.

Карточка принята владельцем переходом к следующему этапу 2026-09-13. В локальной тестовой базе оставлены только изолированные данные `I03 Проверка`; push не выполнялся. Несовместимый глобальный override `path-to-regexp`, ломавший закреплённый `serve-handler`, ограничен зависимостью Express 4; штатный production start и deep-link rewrite работают. Встроенный браузер Codex добавляет собственный `codex-browser-sidebar-comments-root` непосредственно под `<html>` до запуска приложения и тем самым создаёт ложный hydration mismatch; контрольная проверка гидратации выполнена в чистом headless Chrome без этой DOM-инъекции.

## Rollback

Feature flag shell/brand возвращает baseline routes. Auth/data migrations отсутствуют либо additive.

## Stop rules

- требуется новый auth;
- route rewrite ломает existing links;
- brand removal затрагивает mandatory legal notice;
- translation меняет API/internal identifiers.
