# G1.2 — Git projections и code RAG

## Пользовательский результат

Команда размещает repository, branch, commit и pull request на Canvas, а `Спросить проект` использует разрешённые сведения о коде и всегда показывает источник ответа.

## Зависимости

- G1.1 accepted;
- I1.2 accepted;
- AF0.3 accepted;
- утверждена code-indexing policy;
- [../07 — Холст и проекции сущностей](<../07 — Холст и проекции сущностей.md>);
- [../08 — Project Brain, Hybrid RAG и граф знаний](<../08 — Project Brain, Hybrid RAG и граф знаний.md>).

## Scope

- Canvas projections для repository, branch, commit и pull request;
- карточки со статусом, автором, ссылкой и связанными Work Items;
- обновление projection по нормализованным Git events;
- allowlist repositories и branches для индексации;
- language-aware chunking поддерживаемых текстовых файлов;
- исключения для secrets, binaries, generated/vendor paths;
- code chunks с commit SHA, path и line-range metadata;
- гибридный retrieval по знаниям проекта и коду;
- citations на provider URL и конкретный commit;
- purge/reindex при revoke, force-push или изменении policy;
- лимиты размера, частоты и стоимости.

## Не входит

- выполнение кода из repository;
- индексация секретов, бинарников и всего Git history без ограничений;
- автоматический merge;
- замена специализированного code search/IDE;
- запись в repository AI-агентом.

## Порядок реализации

1. Утвердить code-indexing policy и deny patterns.
2. Добавить Git projection renderers и canonical deep links.
3. Реализовать получение разрешённого snapshot по commit SHA.
4. Добавить secret scan и file filters до индексации.
5. Реализовать language-aware chunking и metadata.
6. Подключить code chunks к project-isolated retrieval.
7. Добавить citations до файла, SHA и строк.
8. Реализовать incremental reindex и purge.
9. Добавить наблюдаемость стоимости и качества.
10. Проверить сценарии изменения прав и удаления repository binding.

## Критерии приёмки

1. Проекция Git-сущности не копирует её бизнес-состояние как независимую запись.
2. Обновление PR у provider отражается на Canvas после обработки события.
3. Ответ по коду содержит repository, commit SHA, path и диапазон строк либо честно сообщает об отсутствии источника.
4. Данные другого project не попадают в retrieval.
5. Deny paths, binaries и найденные secrets не индексируются.
6. Revoke запускает предсказуемую остановку синхронизации и purge согласно policy.
7. Старые chunks не выдаются как актуальные после reindex нового SHA.

## Проверки

- projection update;
- source URL and SHA stability;
- cross-project isolation;
- secret/binary/vendor exclusion;
- force-push and deleted branch;
- revoked provider access;
- stale chunk purge;
- groundedness/citation evaluation на контрольном наборе.

## Реализовано локально

- живые проекции repository, branch, commit и pull request на Canvas без копирования их бизнес-состояния в документ доски;
- канонические ссылки на Git provider, текущий статус объекта и связи с Work Items;
- обновление проекций из нормализованных Git events с project isolation;
- явное включение индексации кода для конкретного repository и branch;
- безопасное получение snapshot по точному commit SHA с лимитами файлов и общего объёма;
- исключение бинарных файлов, секретов, `.env`, lock-файлов, generated/vendor paths и неподдерживаемых расширений до загрузки содержимого;
- language-aware chunks с repository, commit SHA, path и диапазоном строк;
- подключение разрешённых code chunks к `Спросить проект` и цитаты до точного файла и строк;
- reindex/purge при изменении policy, новом SHA, удалении индексируемой branch и отзыве GitHub App installation;
- экран управления индексом в разделе `Код`: состояние, branch, SHA, объём и безопасное отключение с удалением производного индекса;
- быстрые действия `На холст` для repository и Git objects.

Локальная проверка 2026-09-20: `75` contract-тестов Git/Brain/Canvas, `26` тестов пакета Canvas,
проверки типов и production build web прошли. UI проверен в локальном браузере на реальном проекте PPM.
