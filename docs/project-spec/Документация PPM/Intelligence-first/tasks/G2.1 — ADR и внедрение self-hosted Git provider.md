# G2.1 — ADR и внедрение self-hosted Git provider

## Пользовательский результат

Команды хранят код на **своём** Git-сервере рядом с PPM: обычные `git clone`/`push`/`pull`, ветки и запросы на
слияние (PR) — на `git.<домен>`. PPM видит репозитории проектов, коммиты и PR, сам связывает их с задачами по ключу
(`ROBOT-12: …`), ищет по коду и показывает Git-карточки на Холсте. Администраторы видят и скачивают код любой команды.
PPM подключает Git-сервер, а не реализует его сам.

## Решение владельца (2026-09-28)

- Git-сервер — **Forgejo 15 LTS**; решение и сравнение с GitLab CE —
  [Решение — Forgejo как собственный Git-сервер PPM](<../Решение — Forgejo как собственный Git-сервер PPM.md>).
- Объём — **«Быстрый»**: в Forgejo свои учётные записи, людей и доступы заводит администратор в Forgejo. Единый вход
  через PPM и автодоступы по проектам — G2.2; вставка коммитов в отчёты и автосводка — G2.3.
- PPM и Forgejo выкладываются на сервер **вместе**; выкладка RC.1 отдельно не делается.
- «Делай до конца»: спецификация и план записываются в документацию, работа идёт без промежуточных согласований;
  коммиты локальные (по коммиту на волну), без push.

## Зависимости

- G1.1/G1.2 (`review`) — провайдерная модель, автосвязь, индексация кода; выделяемый контракт не меняет их поведение.
- Комплект развёртывания RC.1 (`plane-fork/deployments/ppm`, O0.1).

## Scope

### A. Общий провайдерный контракт («разъём»)
- **R1.** В `ppm_git/providers/base.py` — контракт чтения провайдера (`Protocol`), в `ppm_git/providers/__init__.py`
  — реестр `get_provider_client(provider)`. Синхронизация, индексация кода и обработка доставок вызывают клиента через
  реестр по `provider` подключения/доставки. GitHub-специфичные потоки (установка GitHub App, OAuth, запись G1.3,
  команда статуса вебхука) остаются GitHub-only.
- **R2.** Поведение GitHub не меняется: весь `tests/contract/ppm_git` зелёный; правки тестов — только точки подмены.

### B. Провайдер Forgejo (API)
- **R3.** Значение `PpmGitProvider.FORGEJO = "forgejo"` (миграция только choices).
- **R4.** Настройки из окружения: `PPM_FORGEJO_URL` (внутренний адрес API, `http://forgejo:3000`),
  `PPM_FORGEJO_PUBLIC_URL` (`https://git.<домен>`), `PPM_FORGEJO_TOKEN`, `PPM_FORGEJO_WEBHOOK_SECRET` (секреты).
  Провайдер включён только при всех четырёх. Секреты не уходят в браузер, API-ответы, логи и аудит.
- **R5.** `ForgejoClient` реализует контракт по Forgejo API v1: таймауты, постраничная выборка, 429/5xx → ожидание
  (`PpmGitProviderRateLimited`), ошибки → `PpmGitProviderError` с безопасным текстом; нормализованные данные той же
  формы, что у GitHub (репозиторий, ветки, коммиты, PR с `merged_at`), канонические ссылки — публичный адрес Forgejo.
- **R6.** Приёмник `POST /api/ppm/v1/git/forgejo/webhook/`: сырое тело до разбора, ограничение размера, подпись
  `X-Forgejo-Signature` (HMAC-SHA256, hex, сравнение за постоянное время), обязательные `X-Forgejo-Delivery` и
  `X-Forgejo-Event`, идемпотентная квитанция `PpmGitDelivery(provider=forgejo)`, обработка в фоне. События: `push`,
  `pull_request`, `create`/`delete` (ветки), `repository` (удаление → ошибка подключения). Репозитории без активного
  подключения и неизвестные события — принять и не менять данные.
- **R7.** Подключение: список репозиториев Forgejo (поиск, страницы, отметка «уже подключён») и подключение
  репозитория к проекту; отключение — общим действием. **Подключать и отключать репозитории Forgejo может только
  глобальный администратор PPM** (служебная учётка видит весь код). Совпадение с ручной записью G0.1 по канонической
  ссылке — как у GitHub. Аудит подключения и отключения.
- **R8.** Сверка по расписанию, первичная синхронизация, индексация кода и автосвязь с задачами работают для Forgejo
  так же, как для GitHub.
- **R9.** Сводка провайдеров (`provider_summary`) и обзор «Код» отдают провайдер каждого репозитория и признак
  «Git-сервер настроен» — без секретов.

### C. Раздел «Код» (web)
- **R10.** Кнопка «Подключить с нашего Git-сервера» (видна глобальному администратору, если Forgejo настроен;
  остальным — подсказка «Репозиторий подключает администратор PPM») и диалог выбора репозитория (поиск, приватность,
  «уже подключён»).
- **R11.** Надписи не привязаны к бренду: подключённый репозиторий показывает своего провайдера («GitHub» /
  «Наш Git-сервер»), ссылки «Открыть на Git-сервере ↗», статусы вида «Git-сервер просит подождать».
- **R12.** У репозитория — «Как скачать код»: команды `git clone` по HTTPS и SSH с кнопкой копирования.
- **R13.** Строки по-русски, облик v1 и v2 не ломается; vitest/tsc/oxlint — в пределах базы.

### D. Forgejo в комплекте развёртывания
- **R14.** Сервис `forgejo` (образ `15-rootless`, закреплён по digest), настройки только переменными `FORGEJO__…`:
  закрытая регистрация, без входа ничего не видно, приватные репозитории и организации по умолчанию, создание
  репозитория `git push` (приватный), без почты, без проверки обновлений, без Actions и пакетов, вебхуки только на
  внутренний API PPM; встроенный SSH на `2222` (выключаемый).
- **R15.** Отдельные база `forgejo` и роль в том же PostgreSQL — идемпотентная инициализация перед стартом Forgejo.
- **R16.** Caddy: сайт `git.<домен>` → Forgejo (тот же режим TLS), заголовки безопасности, скрытие секретов в логах
  (Authorization, Cookie, строка запроса), большие тела и долгие запросы для `git push`.
- **R17.** `ppm-env.sh`: ключи Git-сервера и секреты Forgejo генерируются при `init`; для существующего файла —
  команда, добавляющая недостающие ключи, ничего не меняя в остальных; `check` их проверяет; шаблон обновлён.
- **R18.** `ppm-deploy.sh`: идемпотентная первичная настройка Git-сервера — служебная учётка `ppm-bot`, токен PPM
  только на чтение (в окружение, 600, с перевыпуском по запросу), системный вебхук на приёмник PPM; учётка
  администратора для владельца (случайный пароль со сменой при первом входе, пароль — только в файле 600).
- **R19.** Резервные копии: база `forgejo` и данные Forgejo — в том же зашифрованном архиве; восстановление и
  учения проверяют их; старые архивы без Forgejo восстанавливаются как раньше.
- **R20.** RUNBOOK (по-русски): DNS и порты, первичная настройка, люди/организации/команды/доступы, «администратор
  видит весь код», быстрый старт разработчика (SSH-ключ или токен, clone, push, PR), перенос с GitHub, подключение
  репозитория к проекту PPM, обновление, бэкап и восстановление, выключение SSH, ограничения. `cli-checks.sh` покрывает
  новое.
- **R21.** Безопасность: наружу — только HTTPS через Caddy и SSH-порт; у Forgejo нет исходящих запросов в интернет;
  токен PPM только на чтение; секреты не печатаются.

### E. Сквозная проверка и приёмка
- **R22.** На одноразовом локальном стеке: первичная настройка → тестовые пользователь, организация, репозиторий →
  администратор PPM подключает репозиторий к тестовому проекту → `git push` (HTTPS и SSH) коммита `KEY-1: …` → коммит
  у задачи KEY-1 в PPM не позже 30 с → PR открыт и слит — статус и время слияния в PPM → поиск по коду находит файл →
  отключение сохраняет историю → бэкап и восстановление в отдельный проект сохраняют репозиторий и связи в PPM.
- **R23.** Проверка интерфейса «Код» в браузере на том же стеке (подключение, команды clone, надписи провайдера).
- **R24.** Ревью безопасности (приёмник, токены, права подключения, Caddy); регрессии: `ppm_git`, `ppm_canvas`,
  `ppm_vault`, `ppm_brain` целиком, web vitest/tsc/oxlint.

## Не входит

- собственный Git protocol, object store, merge engine и просмотрщик кода/diff/ревью в PPM (это даёт Forgejo);
- единый вход и автодоступы (G2.2), вставка коммитов в отчёты и автосводка (G2.3);
- запись в Git из PPM (ветка и черновой PR) для Forgejo, Forgejo Actions, реестр пакетов;
- автоматический перенос репозиториев с GitHub (есть встроенная миграция Forgejo, описывается в RUNBOOK);
- статус Git в центре администратора (отдельная доработка ADM0.1).

## Порядок реализации

1. Контракт и реестр провайдеров без изменения поведения GitHub (R1–R2).
2. Параллельно: Forgejo в комплекте развёртывания (R14–R21).
3. Клиент Forgejo, приёмник, подключение, сверка (R3–R9) и раздел «Код» (R10–R13).
4. Сквозная проверка, браузер, ревью безопасности, учения восстановления (R22–R24).
5. CHANGELOG, статусы, дополнение к release notes; коммиты по волнам.

## Критерии приёмки

1. `git clone`, `fetch`, `push`, ветки и PR к `git.<домен>` работают по HTTPS и SSH из терминала и VS Code.
2. PPM показывает коммиты и PR подключённых репозиториев Forgejo и связывает их с задачами по ключу; события приходят
   подписанным вебхуком, пропущенные восстанавливает сверка.
3. Репозитории Forgejo подключает только глобальный администратор PPM; участники видят Git только своих проектов.
4. Архив резервной копии содержит Forgejo; учения восстановления пройдены.
5. Интеграция с GitHub работает как раньше (контрактные тесты зелёные).
6. Интерфейс по-русски и не привязан к бренду провайдера.
7. По RUNBOOK владелец заводит людей, команды и доступы, а разработчик начинает работу.

## Проверки

- контрактные тесты клиента Forgejo на поддельном Forgejo и приёмника (подпись, повтор, размер, неизвестные события);
- реестр провайдеров и регрессии GitHub;
- права подключения (администратор / РП / участник / чужой проект);
- `cli-checks.sh`, пробное развёртывание с `tls internal`;
- сквозной сценарий R22 на живом Forgejo 15 в одноразовом стеке;
- учения бэкап → восстановление с Forgejo;
- поиск секретов в логах (`ppm-deploy.sh scan-logs`).

## Rollback

Пустые `PPM_FORGEJO_*` выключают провайдер: подключения Forgejo помечаются недоступными, история, ссылки и карточки
остаются, GitHub не затрагивается. Сервис Forgejo останавливается отдельно от PPM; данные остаются в томе и в
резервных копиях. Удаление данных Forgejo — только отдельным подтверждённым действием владельца.
