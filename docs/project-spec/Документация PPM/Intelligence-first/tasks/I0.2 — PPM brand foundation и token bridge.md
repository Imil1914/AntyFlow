# I0.2 — PPM brand foundation и token bridge

## Пользовательский результат

Базовые компоненты Plane получают палитру, typography и assets AntyFlow через единый слой, не ломая функциональность и не создавая неуправляемый fork diff.

## Зависимости

- I0.1 baseline доказан;
- [../11 — AntyFlow дизайн-система и полный ребрендинг Plane](<../11 — AntyFlow дизайн-система и полный ребрендинг Plane.md>);
- временные PPM logo/name разрешены до утверждения финального бренда.

## Scope

- inventory user-facing brand surfaces;
- package/module `ppm-brand`;
- Graphite и Light tokens;
- IBM Plex Sans/JetBrains Mono либо утверждённый local-hosted font setup;
- token bridge к Plane/Propel semantic variables;
- PPM logo placeholder, favicon/PWA assets;
- app title/meta;
- base components smoke;
- feature flag `PPM_BRAND_ENABLED`;
- legal/source route skeleton.

## Не входит

- redesign всех страниц;
- новая navigation;
- email/admin/public surface tail;
- переименование `@plane/*` packages;
- изменение business logic.

## Порядок реализации

1. Найти реальные theme entrypoints и assets в pinned source.
2. Сохранить inventory с path и surface.
3. Добавить semantic PPM tokens без global hex replace.
4. Подключить tokens через `custom`/PPM theme.
5. Создать адаптер существующих Plane variables.
6. Добавить fonts с учётом CSP/offline/self-hosting.
7. Заменить root meta/favicon/logo entrypoints.
8. Добавить legal route с upstream/tag/fork placeholders из build manifest.
9. Проверить representative components.
10. Добавить screenshots Graphite/Light.

## Критерии приёмки

1. Один файл/пакет является источником основных PPM tokens.
2. Главный accent `#22D3EE`, темы визуально соответствуют AntyFlow foundation.
3. Root title/favicon/logo не Plane.
4. Base Button/Input/Dialog/Toast читаемы в двух темах.
5. Выключение flag возвращает baseline theme без data changes.
6. Legal/source route существует.
7. Upstream package names не переименованы.

## Проверки

- typecheck/build;
- token fallback test;
- visual snapshots;
- contrast/focus smoke;
- grep user-facing `Plane` inventory, без требования очистить хвостовые surfaces в этой задаче;
- baseline Work Item smoke.

## Rollback

Выключить `PPM_BRAND_ENABLED` или revert isolated theme commit. Миграций данных нет.

## Stop rules

- нет утверждённого временного asset и изменение требует выдумать новый бренд;
- token bridge требует массового изменения сотен бизнес-компонентов;
- font licensing/self-hosting неясны;
- изменение ломает clean Plane baseline.

## Реализовано

- `@ppm/brand` является единым источником названия, assets, переводов и foundation tokens PPM.
- Graphite и Light подключены через gated semantic bridge к существующим Plane/Propel variables без массового
  изменения бизнес-компонентов.
- Основной accent зафиксирован как `#22D3EE`; IBM Plex Sans и JetBrains Mono поставляются локально в web bundle.
- Root title/meta, PWA manifest, favicon и ProductLogo переключаются через `PPM_BRAND_ENABLED`.
- Добавлены PPM mark/lockup, `/about/brand-foundation` и `/about/open-source`.
- Ссылка `Исходный код PPM` исправлена на главный repository `https://github.com/Imil1914/PPM`; pinned Plane fork
  остаётся только в build manifest для лицензии и воспроизводимости.
- Инвентаризация точек подключения сохранена в `docs/ppm/brand-surface-inventory.md`.
- E1 browser gate проверяет реальные Button/Input/Dialog/Toast в Light и Graphite и сохраняет визуальный attachment.
