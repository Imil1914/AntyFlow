# AF2.2 — Живая карта проекта: сборка из спринта, светофор, «Не на карте», «Что изменилось»

## Пользовательский результат

На еженедельной планёрке команда открывает «Карту проекта» и за 10 секунд видит спринт, задачи по направлениям,
проблемы и всё, что изменилось с прошлого раза. Карта собирается одной кнопкой из данных Plane, живёт как обычная доска
Холста и ничего не меняет сама.

Подпроект П2 программы «Холст 2.0» (П1 AF2.1 «Инструменты Холста» → **П2** → П3 «Комментарии и совместная работа»).
Решения владельца 2026-09-25/26: сценарий «Карта проекта» (еженедельная планёрка), путь А «Живая карта», сервер можно
менять; «Что изменилось» — у каждого своя отметка; дизайн (вариант А — лента на сервере по запросу) утверждён,
«делай до конца» без промежуточных согласований; без коммитов.

## Основание

- Макет: https://claude.ai/artifact/V1QNwpNrKnifh5aaJ9NCCe, ряд «K · Холст 2.0», артборды K5 «Живая карта» (светлая и
  тёмная); локально `docs/superpowers/plans/2026-09-25-af21/mockups/K5-Living-Map.png|.dc.html`, бриф
  `docs/superpowers/plans/2026-09-25-af21/notes/K-BRIEF.md` (п. 9).
- Разведка данных (2026-09-26): «Направления» = Plane Modules; «Спринты» = Plane Cycles (текущий — `status == "current"`,
  прогресс — `…/cycles/{id}/progress/`, шкала «День N из M» — `ppm-tasks/sprint.ts` `computePpmSprintScale`); связи задач
  — Plane `IssueRelation` (на Холст сейчас не выводятся); история задач — `IssueActivity` (есть только по задаче);
  PR — `PpmGitObject`/`PpmGitLink`; версии файлов — `PpmVaultVersion`; версии досок — `PpmCanvasVersion` (полный снимок
  на каждое сохранение); узлы PPM несут `author_id`, `created_at`, `updated_at`. Нет: ленты изменений по проекту, личной
  отметки «просмотрено», поиска досок по задаче.

## Scope

### A. «Собрать карту спринта»
- Команда в рейке v2 («Из проекта ▸ Карта спринта»), в палитре команд и кнопка в пустом состоянии новой доски.
- Диалог: выбор спринта (текущий выбран по умолчанию; также ближайшие и завершённые за 60 дней), группировка — по
  направлениям (модулям). Кнопка «Собрать карту».
- Создаётся **новая доска** «Карта · {название спринта}» (существующие доски не меняются), на ней:
  - рамка спринта — узел PPM `group` с `map: { role: "sprint", cycle_id }`: заголовок «Спринт · даты», живая шкала
    «День N из M · K из T задач готово», ссылка «Открыть в Спринтах ↗»;
  - секции по направлениям — узлы PPM `group` с `map: { role: "section", module_id }` внутри рамки спринта; задачи без
    направления — секция «Без направления» (`module_id: null`); задача в нескольких направлениях — в первом по названию;
  - живые карточки задач (существующая карточка `work_item_ref`) сеткой внутри секций (до 4 колонок, без наложений);
  - всё создаётся одним шагом истории; привязки — одним пакетным запросом (A-S1).
- Узел `group` расширяется необязательным полем `map` (схема версии 2, неизвестные поля сохраняются; старые доски и
  группы без `map` — без изменений).

### B. Связи из Plane («из Задач»)
- Между задачами, лежащими на доске, рисуются связи Plane: `blocked_by` → «Блокирует» (от блокирующей к заблокированной,
  конец ⊣), `start_before`/`finish_before` → «Зависит от», `relates_to` → «Связано», `implemented_by` → «Реализует»;
  `duplicate` — не рисуется. Чип связи: «{тип} · из Задач».
- Связи производные: вычисляются при открытии доски и обновлении данных, в снимок доски и в `ppm_semantic_edges` не
  пишутся; править их на доске нельзя (подсказка «Изменяется в Задачах»). Работают на любой доске v2, где есть живые
  карточки задач.

### C. «Светофор»
- Переключатель «Светофор» в правом верхнем углу доски (рядом с «Доска · Объектов»), виден, если на доске есть живые
  карточки задач; по умолчанию включён; хранится у пользователя в браузере.
- Правила для живой карточки задачи: просрочена (срок < сегодня по местному времени и группа статуса не
  completed/cancelled) — оранжевая рамка и строка «просрочено · {дата}»; заблокирована (есть незавершённая блокирующая
  задача) — красная рамка и строка «заблокирована {ID}» (имеет приоритет над «просрочено»); готова (completed) —
  приглушена. В заголовках секций карты — счётчики «N просрочено», «N заблокирована».

### D. Лоток «Не на карте»
- На доске-карте (есть рамка спринта): панель «Не на карте · N» — задачи спринта, которых нет на доске, и PR, связанные
  с задачами спринта, которых нет на доске. У пункта — «+ Добавить» (в секцию своего направления, свободное место, без
  наложений); «Разложить всё» — добавить всё. Автоматически ничего не добавляется. Только редакторы; читатель видит
  список без кнопок.

### E. «Что изменилось с …»
- Кнопка «Что изменилось · N» на доске v2 и панель справа (как K5): заголовок «Что изменилось с {дата} · N», лента
  событий (значок, текст, кто, когда), клик по событию выделяет и показывает карточку на доске (если она есть), внизу —
  «Отметить просмотренным».
- Отметка — у каждого своя, хранится на сервере (A-S3): по умолчанию «с последнего просмотра» (если отметки нет —
  с момента создания доски, но не раньше 7 дней назад); переключатель «с последнего просмотра · с начала спринта (на
  карте) · с даты…».
- События (A-S2): статус, исполнители, срок, приоритет, название задач на доске и задач спринта карты; новые/удалённые
  связи задач; PR открыт и PR влит (для этих задач); новая версия файла Хранилища на доске; на самой доске — добавленные
  и изменённые карточки PPM (автор — `author_id`, изменения — по `updated_at`) и добавленные стикеры/фигуры/текст (по
  сравнению с версией доски на момент отметки; автор неизвестен — «на доске»). Перемещение карточек изменением не
  считается.
- Метки «изменено» / «добавлено» на карточках, к которым относятся события, пока у пользователя есть непросмотренные
  изменения; после «Отметить просмотренным» исчезают.
- Лента обновляется при открытии панели, при возврате на вкладку и раз в 60 с, пока панель открыта. Окно — не больше 30
  дней, не больше 200 событий (новые первыми), признак «показаны не все».

### F. «На карте» в задаче
- В карточке задачи Plane (боковая панель деталей и превью) — строка «На карте» со списком досок, где задача лежит
  живой карточкой, и ссылками на доску (открывает доску и выделяет карточку). Только доски, которые пользователь может
  читать; архивные — нет. Только в новом облике.

### Сервер (A-S*)
- **S1. Пакетная привязка:** `POST /api/ppm/v1/workspaces/<ws>/projects/<pid>/canvas/boards/<bid>/bindings/batch/` —
  до 200 пунктов `{shape_id, entity_type, entity_id, client_operation_id?}`, та же семантика и проверки, что у одиночной
  привязки (pending до сохранения доски), ответ по каждому пункту (привязка или код ошибки), права — редактирование доски.
- **S2. Лента изменений:** `GET …/canvas/boards/<bid>/changes/?since=<ISO 8601>&limit=<≤200>` → `{ since, until, items:
  [{ id, kind, occurred_at, actor: {id, display_name} | null, entity: {type, id, identifier?, title?}, shape_ids: [],
  detail: {field?, old?, new?} }], truncated }`. Виды: `work_item.state|assignees|due|priority|name|relation`,
  `git.pull_request.opened|merged`, `vault.version`, `board.node.added|changed`. Источники — `IssueActivity`,
  `PpmGitLink`/`PpmGitObject`, `PpmVaultVersion`, текущий снимок и версия доски на момент `since` (`PpmCanvasVersion`).
  Видимость — по правилам Plane и PPM (гости, приватные документы/файлы); без выдержек содержимого. Лимиты: `since` не
  раньше 30 дней (иначе обрезается, `truncated: true`), не больше 200 событий.
- **S3. Отметка просмотра:** модель `PpmCanvasBoardUserState(board, user, seen_at, seen_version)` (уникальна по паре) +
  миграция; `GET …/boards/<bid>/me/` → `{ seen_at, seen_version }` или пусто; `PUT …/boards/<bid>/me/seen/` → серверное
  «сейчас» и текущая версия доски. Права — чтение доски.
- **S4. Доски задачи:** `GET /api/ppm/v1/workspaces/<ws>/projects/<pid>/canvas/work-items/<id>/boards/` → `{ results:
  [{ board_id, name, shape_id }] }` по активным привязкам, без архивных досок, только читаемые пользователем, с
  проверкой видимости самой задачи.

## Не входит
- Живые обновления по WebSocket (лента опрашивается), авто-перестройка карты, несколько спринтов на одной карте,
  графики сгорания, комментарии и упоминания (П3), ИИ.

## Контракты и инварианты
- Всё новое на клиенте — только под грамматикой Холста v2 (облик v2 + рабочее пространство); облик v1 и минимальный
  режим не меняются; старые доски открываются как раньше.
- Ничего не пишется в доску без действия пользователя (сборка, «+ Добавить», «Разложить всё» — только по нажатию).
- Задачи, связи, PR, файлы живут в своих источниках; на доске — ссылки и визуальные свойства; связи «из Задач» не
  хранятся на доске.
- Права проверяет сервер; лента не раскрывает сущности, невидимые пользователю.
- Схема узлов — версия 2, новые поля необязательны и обратно совместимы (тест миграции).
- Горячие клавиши — `e.code`; строки — в модуле переводов `@ppm/brand` (en и ru); без ИИ и новых внешних запросов.
- Производительность: сборка карты на 50 задач ≤ 5 с; лента ≤ 1 с на доске с 300 фигурами; без перерисовок на каждом
  кадре камеры.

## Критерии приёмки
1. «Собрать карту спринта» создаёт новую доску с рамкой спринта (живая шкала), секциями по направлениям и живыми
   карточками всех задач спринта; связи «из Задач» нарисованы; существующие доски не меняются.
2. «Светофор»: просроченные, заблокированные и готовые задачи выделяются по правилам; счётчики в секциях; переключатель
   запоминается.
3. «Не на карте» показывает задачи спринта и PR, которых нет на доске; «+ Добавить» кладёт в нужную секцию;
   «Разложить всё» — всё; ничего не добавляется само.
4. «Что изменилось с …» показывает события перечисленных видов с личной отметки; метки на карточках; «Отметить
   просмотренным» сбрасывает только у себя; «с начала спринта» и «с даты» работают; читатель видит ленту.
5. В задаче видно «На карте» со ссылками только на доступные доски.
6. Проверки не хуже базовой линии после AF2.1 (web vitest, brand, canvas, root, tsc 0, oxlint 719/0, API pytest), новые
   тесты зелёные; живая проверка на тестовых досках проекта 228.

## Решения исполнителя
| # | Вопрос | Решение |
|---|---|---|
| R1 | Где хранить конфигурацию карты | Необязательное поле `map` у узла `group` (рамка спринта и секции), не отдельная таблица |
| R2 | Сборка на клиенте или сервере | На клиенте существующими фабриками узлов; сервер — только пакетная привязка (S1) |
| R3 | Связи из Plane | Производные, не хранятся; только между задачами на доске; правка — в Задачах |
| R4 | Как считать «Что изменилось» | Лента на сервере по запросу из существующих данных (вариант А), без журнала событий |
| R5 | Отметка просмотра | Личная, на сервере (S3); по умолчанию — с последней отметки, иначе с создания доски, не раньше 7 дней |
| R6 | Изменения на доске | Карточки PPM — по `created_at`/`updated_at`; нативные фигуры — «добавлено» по сравнению с версией доски; перемещение не событие |
| R7 | Задача в нескольких направлениях | Кладётся в первую по названию секцию |
| R8 | Обновление ленты | Опрос раз в 60 с при открытой панели, при открытии и возврате на вкладку; без WebSocket |
| R9 | Свои действия в ленте | В режиме «с последнего просмотра» свои события не показываются (счётчик, список, метки) и убираются до свёртки — чужая правка на моей карточке не теряется; в «с начала спринта» и «с даты» видны |
| R10 | Правая колонка | Инспектор скрыт, пока открыта панель «Что изменилось» или развёрнут лоток; лоток свёрнут по умолчанию, выбор запоминается по пользователю и доске |
| R11 | Отметка у сборщика | Карта отмечается просмотренной для того, кто её собрал, после первого успешного сохранения сборки |
| R12 | Исходное содержимое доски | Фигуры первой сохранённой версии (собранная карта, копия доски) никогда не «добавлено»; «изменено» — только если правку записала более поздняя версия. Уточняет R5: без отметки — с создания доски, но исходное содержимое не новость |
| R13 | Пределы размеров групп | Обычные группы — прежние 1600 × 1200; до 20 000 px — только группы карты; копия группы карты — обычная секция, прижата к 1600 × 1200 |
| R14 | Удаление секции или рамки | Во всех обликах живые карточки группы переносятся на страницу на те же места (страж целостности); «Отменить» возвращает одним шагом |
| R15 | Надёжность сборки | Только на новой пустой доске; доска создаётся после проверки свободной вкладки (≤ 8) и непустого спринта; один шаг истории; при сбое после пакетной привязки — отмена всех её привязок и откат фигур |
| R16 | Очень большие спринты | Секции сверх высоты рамки 20 000 px уходят в лоток «Не на карте» (число — в уведомлении) |
| R17 | Лоток | «Разложить всё» — до 200 за нажатие и не больше места в ближайшем сохранении; ручная ссылка на PR без объекта Git видна, но не кладётся; PR нескольких задач — один пункт (у задачи с меньшим номером); PR, закрытые без слияния, не показываются |
| R18 | Время событий Git и фигур | «Влит» — настоящее время слияния (`provider_merged_at`, миграция `ppm_git 0006`); «добавлено/изменено» у фигур пишется при сохранении версии (`added_shape_ids`/`changed_shape_ids`, миграция `ppm_canvas 0010`) с автором версии; PR, впервые увиденный уже влитым, не даёт «открыт» |
| R19 | Какая рамка спринта главная | Клиент (шапка, «с начала спринта», лоток) — первая рамка спринта верхнего уровня в порядке страницы; лента сервера берёт задачи всех рамок спринта доски (≤ 10) |
| R20 | «На карте» | Только облик v2 с включённым Холстом и оболочкой AntyFlow; ссылка на доску, которую нельзя открыть (8 вкладок), показывает предупреждение о пределе, а не тихий переход (так и в прежнем облике рабочего пространства AntyFlow) |
| R21 | «Светофор» вне спринта карты | Связи — из последних 1000 изменённых задач проекта, список перечитывается не чаще раза в 5 минут (ограничение, в CHANGELOG) |
| R22 | Стоимость пакетной привязки | Видимость задач проверяется одним запросом на пакет по правилам одиночной привязки: 200 карточек — ≈ 0,35 с вместо ≈ 1 с |
| R23 | Контраст «просрочено» | Контракт токенов проверяет текст предупреждения там, где его рисует карта (фон живой карточки и секции, ≥ 4,5:1 в обеих темах); общий светлый токен предупреждения ниже 4,5:1 на части других поверхностей (наследие UX1.1) — отдельная задача |

## Реализовано 2026-09-26

Все 16 задач (линии F, S, C, M и серверная правка S2a; планы линий — `docs/superpowers/plans/2026-09-26-af22/drafts/`)
выполнены без коммитов; у каждой — отдельное ревью (у сборки и лотка — по два раунда), затем итоговое ревью всей ветки
(«Ready to ship: Yes with fixes»), одна волна исправлений из двух параллельных линий (сервер и клиент) с повторной
проверкой каждой и живая проверка на новой доске «Карта · Cycle 1: Getting Started with Plane» (проект 228). Журнал
решений и раундов — `.superpowers/sdd/2026-09-26-af22-living-map/progress.md`; отчёты — там же. Изменения для
пользователя, ограничения и проверки — запись «2026-09-26 — AF2.2» в `CHANGELOG.md`.

Критерии приёмки:
1. Сборка карты — выполнено: новая доска, рамка спринта с живой шкалой, секции по направлениям, живые карточки всех
   задач спринта; старые доски не меняются (живая проверка: 4 задачи меньше чем за секунду, «Отменить»/«Повторить»,
   удаление секции и отмена одним шагом). Связи «из Задач» — проверены на подменённом в браузере ответе Plane (задачи
   владельца не менялись): линия «Блокирует», строка «заблокирована 228-3», счётчик секции; у соседних карточек — короткий
   штрих без подписи (ограничение в CHANGELOG).
