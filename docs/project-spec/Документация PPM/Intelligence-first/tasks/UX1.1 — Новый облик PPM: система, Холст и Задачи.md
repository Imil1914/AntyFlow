# UX1.1 — Новый облик PPM: система, Холст и Задачи (гибрид A+B)

## Пользовательский результат

PPM выглядит как собственный продукт, а не перекрашенный Plane: спокойный тёплый графит и «бумага» в светлой теме,
один сдержанный голубой акцент, IBM Plex с узким начертанием для плотных мест, удобная или компактная плотность на
выбор. На Холсте видно, что откуда: живые карточки источников, свои заметки и найденное поиском различаются с первого
взгляда, смысловые связи нарисованы прямо на холсте и читаются по концу линии. В Задачах видно ход спринта, «полоску
доказательств» у каждой задачи и то, что требует внимания куратора.

Это «волна 1» дизайн-программы PPM. Волна 0 (UX0.2) — исправления; волна 2 (остальные экраны) отложена
владельцем 2026-09-24.

## Основание

- Решения владельца 2026-09-23/24: облик «гибрид A+B» (основа «Тихий графит» + смысловые приёмы «Чертёжной тетради»
  и колонка куратора из «Студии»); объём — система + Холст + Задачи; акцент — спокойный голубой; тема по умолчанию —
  по настройке системы; плотность «Удобная» по умолчанию + «Компактная» в профиле.
- Макеты H-* на холсте https://claude.ai/artifact/V1QNwpNrKnifh5aaJ9NCCe (ряд «H · Гибрид A+B»).
- Волна 0 (UX0.2) лежит в рабочей копии без коммитов; эта карточка строится поверх неё.
- 2026-09-24 владелец поручил исполнителю самому закрыть открытые вопросы (рекомендованными вариантами) и
  завершить волну за 10–14 часов без промежуточных согласований (рулинг R24).

## Scope

### A. Флаг нового облика и мгновенный откат
- Новый флаг `PPM_DESIGN_V2` (по умолчанию `1`), атрибут `html[data-ppm-design="v2"]`.
- Весь CSS волны 1 — под `:where(html[data-ppm-design="v2"])`; TSX-изменения — под `isPpmDesignV2()`.
- `PPM_DESIGN_V2=0` возвращает вид волны 0 без потери данных.
- Для сравнения «до/после» в одном браузере: `localStorage.ppm_design = "v1"` принудительно включает старый вид
  (инлайн-скрипт до первой отрисовки).

### B. Дизайн-система v2 (всё приложение)
- Токены: тёплый графит (тёмная), «бумага и тушь» (светлая), спокойный голубой акцент и его ступени, статусы,
  категориальная палитра типов объектов равной светлоты, фокус ≠ выделение. Значения — из TOKENS.md макетов.
- Шрифты: IBM Plex Sans с осью ширины (`wdth.css`), IBM Plex Mono 400/500 вместо JetBrains Mono; токен сужения
  `--ppm-font-stretch-narrow: 85%`; preload Plex вместо Inter под брендом.
- Плотность: «Удобная» (контент 14/20, строка 36, пункт сайдбара 32, контролы 32, чипы 28, топбар 48, шапка 52,
  отступ страницы 24) и «Компактная» (13/20, 32, 28, 28, 24, 44, 44, 16); хранится в `localStorage.ppm_density`
  (без записи на сервер), переключатель в «Профиль → Предпочтения», применяется без перезагрузки.
- Тема по умолчанию для новых пользователей — «как в системе»; явный выбор пользователя сохраняется.

### C. Оболочка
- Без «рамки» вокруг контента: разделители — граница шапки и сайдбара.
- Верхняя панель 48/44 с границей снизу, подсказка `Ctrl K` / `⌘K` в поиске.
- Сайдбар: знак PPM в шапке, «Новая задача», пункты 32/28, навигация проекта сгруппирована: «Работа», «Знания».
- Иконки lucide тоньше (визуально 1,5 px), тени только у всплывающих слоёв, радиусы 8 у поповеров и 12 у модалок.
- Строки списков: высота из токена `--ppm-row-height` (и у плейсхолдера виртуализации), заметная подсветка открытой
  в peek строки.

### D. Задачи
- Шкала спринта в шапке (если в проекте включены спринты и есть текущий).
- «Полоска доказательств» в строке: PR (номер из связей Git), материалы (вложения + ссылки); без выдуманных «проверок».
- Колонка куратора справа (≥ 1440 px, скрыта при открытом peek): «Заблокировано», «Просрочено», «Ждёт проверки»
  (только если в проекте есть статус «На проверке»/review), «Недавно изменённые» (кто и когда обновил задачу).
- «Отменена» свёрнута по умолчанию (локально), подписи групп и «Все задачи» по-русски, стандартные английские статусы
  (Backlog/Todo/In Progress/Done/Cancelled/Triage) показываются по-русски (только отображение, данные не меняются).
- Кнопка «Новая задача» с подсказкой реального сочетания `N I`.

### E. Холст
- Смысловые связи нарисованы на холсте отдельным слоем (не стрелками tldraw — данные доски не меняются): конец линии
  по типу (⊣ блокирует, пунктир — противоречит, стрелка — зависит/реализует/основание), подпись на линии, подсветка
  связей выделенного объекта, видны и читателям; предложенные — пунктиром «Предложено».
- Грамматика карточек: живые (глиф «три узла», бейдж источника, «Открыть ↗»), свои (нейтральные, цвет — глифом),
  найденные поиском (пунктир, сам фрагмент, чипы-цитаты с версией; «изменился после поиска» — только когда вычислимо).
- Секции: прозрачные, угловые засечки, «Название · N объектов».
- Строка статуса: «Лист N из M · Все изменения сохранены · 12:41 · 100 %» (без «Версии»), сброс масштаба.
- Инспектор выбранной живой карточки (справа, поверх холста): свойства задачи с правкой через существующую проекцию,
  «Связи на холсте».
- (P2, по возможности) «Решение» — вариант заметки со срезанным углом и блоком «Основание» из связей.

## Не входит

- Вложенные кнопки в выпадающих списках Plane; локализация `@plane/editor`; стартовые данные и статусы в API;
  лента активности проекта (нужен API); проверки PR; локальные ассеты tldraw; новые темы «Обсидиан»; новый знак.
- Серверные доработки (состояние PR, лента изменений, статус «На проверке» в новых проектах) — отдельные
  карточки; бриф для агента бэкенда: `docs/superpowers/plans/2026-09-24-ux11/BACKEND-AGENT-BRIEF.md`.
- Контекстная панель над выделенной карточкой Холста (R23); автоматическое сворачивание сайдбара на Холсте.

## Порядок реализации

1. Фаза F — фундамент и оболочка (последовательно): флаг и режимы, токены v2, шрифты и плотность, переключатель
   плотности, оболочка.
2. Две параллельные линии с непересекающимися файлами: T — «Задачи», C — «Холст».
3. Итоговая проверка всей волны, исправления, живая проверка на запущенном dev-сервере, патч `ux11.patch`.

## Контракты и инварианты

- Бренд/оболочка/Холст-флаги работают как раньше; `PPM_DESIGN_V2=0` = вид волны 0.
- Никаких записей данных ради облика: плотность и свёрнутость — только localStorage.
- Сохраняются все функции: правка задачи на карточке Холста, e2e-якоря (см. notes/risk.md §1.3 и canvas.md).
- Горячие клавиши — `e.code`; строки — `PPM_TRANSLATIONS` (en+ru); аудиты классов/бренда/кегля — зелёные.
- Производительность: слой связей не перерисовывает React при панорамировании; нет теней/фильтров на нодах.
- Без коммитов (как в волне 0): исходники до правки — в `docs/superpowers/plans/2026-09-24-ux11/pre/`,
  изменения волны — `tools/ux11-diff.sh > ux11.patch`.

## Критерии приёмки

1. Контракт токенов v2: текст ≥ 4,5:1, смысловые границы ≥ 3:1 в обеих темах и обеих плотностях.
2. `PPM_DESIGN_V2=0` и `localStorage.ppm_design=v1` дают вид волны 0 (визуальное сравнение публичных маршрутов).
3. Переключение плотности мгновенно, без перезагрузки; список не «прыгает» при прокрутке.
4. Все 9 типов смысловых связей рисуются с правильным концом линии; читатель видит связи.
5. Строка статуса, инспектор, секции с засечками, найденное поиском с фрагментом — как на макете, на реальных данных.
6. Шкала спринта и колонка куратора показывают только вычислимые данные.
7. Все базовые проверки не хуже волны 0 (web 184, brand 41, canvas 38, root 653, tsc 0), новые тесты зелёные;
   детектор: `low-contrast`/`tiny-text` = 0 на экранах PPM; повторный разбор ≥ 30/40.

## Rollback

- Мгновенно: `PPM_DESIGN_V2=0` (нужен перезапуск dev-сервера) или в одном браузере `localStorage.ppm_design = "v1"`
  и перезагрузка страницы.
- Полностью: откат файлов по `pre/` (`cp pre/<путь> plane-fork/<путь>`; файлы с пометкой `.__absent__` удалить).
  Данные пользователей не меняются, поэтому откат безопасен.

## Stop rules

- Любое изменение, требующее записи данных, миграции или нового API, — не делать, вынести в отдельную карточку.
- Если правка ломает e2e-якорь или тест, закреплённый в `notes/risk.md`, — вернуть прежнее поведение под v1 и
  искать решение только под v2.
