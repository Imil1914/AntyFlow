# G1.1 — Первый внешний Git provider и webhooks

## Пользовательский результат

Пользователь подключает поддерживаемый Git-провайдер к проекту и видит в PPM актуальные ветки, коммиты и pull/merge requests без передачи пароля от Git-аккаунта.

## Зависимости

- G0.1 accepted;
- первым provider выбран GitHub; одобрено
  [решение GitHub App](<../Решение — GitHub App как первый внешний Git provider.md>);
- [../10 — Git и контур разработки](<../10 — Git и контур разработки.md>);
- [../13 — Безопасность, права и изоляция](<../13 — Безопасность, права и изоляция.md>).

## Scope

- один provider adapter: GitHub либо GitLab;
- OAuth или GitHub App/provider app flow;
- private key и webhook secret только через server environment/secret files; installation access token создаётся
  по требованию и не сохраняется;
- выбор доступного repository и связь с project;
- минимальные read permissions;
- webhook endpoint, проверка подписи и защита от replay;
- идемпотентная обработка push и pull/merge request событий;
- синхронизация repository, branch, commit и pull request metadata;
- связь Work Item по ручной ссылке и ключу в branch/commit/PR;
- reconciliation job на случай потерянного webhook;
- audit и отзыв подключения.

## Не входит

- hosting Git repositories внутри PPM;
- browser-based IDE;
- выполнение произвольного кода;
- force push, merge и изменение protected branches;
- несколько provider adapters в одной задаче;
- полнотекстовая индексация исходного кода.

## Порядок реализации

1. Зафиксировать ADR с первым provider и минимальными permissions.
2. Реализовать provider interface и первый adapter.
3. Добавить installation/connect flow и безопасное хранение секретов.
4. Реализовать repository picker и project binding.
5. Поднять подписанный webhook endpoint.
6. Нормализовать события в PPM-модель.
7. Реализовать идемпотентный consumer и reconciliation.
8. Показать commits и pull requests в разделе `Код` и Work Item.
9. Добавить disconnect/revoke и аудит.
10. Прогнать сценарий VS Code/Codex: branch → commit → push → PR → связь с тикетом.

## Критерии приёмки

1. Подключение не требует хранения пользовательского пароля или личного SSH-ключа.
2. PPM запрашивает только документированные минимальные permissions.
3. Подписанный webhook обновляет commit/PR metadata не более одного раза.
4. Повтор одного события не создаёт дубликатов.
5. Branch/commit/PR с ключом Work Item связывается с ним автоматически или попадает в очередь подтверждения по утверждённому правилу.
6. Потерянный webhook восстанавливается reconciliation job.
7. После revoke новые API-вызовы provider недоступны, а исторические ссылки остаются читаемыми согласно retention policy.
8. Пользователь видит понятное состояние подключения и последней синхронизации.

## Проверки

- OAuth/app install happy path и отказ;
- encrypted secret storage и secret redaction;
- webhook signature/replay/idempotency;
- rate-limit/backoff;
- repository permission changes;
- reconciliation после пропущенного события;
- disconnect/revoke;
- E2E branch/commit/PR flow.

## Реализовано 2026-09-20

- provider-neutral adapter и GitHub App client с краткоживущими installation tokens;
- официальный двухшаговый install flow: Setup URL фиксирует installation, затем PPM запускает OAuth с `state`
  и PKCE; callback не зависит от локальной browser cookie, но повторно проверяет права РП на сервере;
- project-scoped installation и repository binding: РП видит только свой project, global admin сохраняет
  защищённый доступ ко всем projects;
- repository picker, connection state, ручная синхронизация, disconnect и revoke;
- HMAC-SHA256 webhook receiver с raw-body verification, delivery ID, body hash и idempotency;
- нормализация branch, commit и pull request metadata без сохранения email автора;
- auto-link к Work Item по project identifier в branch/commit/PR;
- Celery consumer, backoff при rate limit и reconciliation каждые 15 минут;
- русская панель GitHub App в разделе `Код`, понятные состояния и сохранение ручного режима G0.1;
- additive migrations применены к локальной БД; 18 contract tests проходят, web typecheck и lint проходят.

## Внешний риск и рабочая конфигурация

Реальный GitHub App создан, установлен только на `Imil1914/PPM` и подключён к локальному PPM. Постоянный
development HTTPS endpoint закреплён через ngrok, а подписанные repository webhook deliveries `ping`, `push` и
`pull_request.synchronize` проверены вживую. GitHub по-прежнему сбрасывает app-level webhook после сохранения,
поэтому для текущего репозитория используется защищённый repository webhook, а reconciliation каждые 15 минут
остаётся резервным каналом.

Настройки GitHub App (полная инструкция: [docs/ppm/github-app-setup.md](../../../../ppm/github-app-setup.md)):

- Setup URL: `<PUBLIC_API_BASE>/api/ppm/v1/git/github/setup/`;
- OAuth Callback URL: `<PUBLIC_API_BASE>/api/ppm/v1/git/github/callback/`;
- `Request user authorization (OAuth) during installation`: выключено — PPM запускает OAuth после Setup URL;
- Webhook URL: `<PUBLIC_API_BASE>/api/ppm/v1/git/github/webhook/`;
- permissions: `Metadata: read`, `Contents: read`, `Pull requests: read`;
- events: `installation`, `installation_repositories`, `push`, `pull_request`;
- секреты сервера: `PPM_GITHUB_APP_ID`, `PPM_GITHUB_APP_SLUG`, `PPM_GITHUB_APP_CLIENT_ID`,
  `PPM_GITHUB_CALLBACK_URL`,
  `PPM_GITHUB_APP_CLIENT_SECRET[_FILE]`, `PPM_GITHUB_APP_PRIVATE_KEY[_FILE]`,
  `PPM_GITHUB_WEBHOOK_SECRET[_FILE]`.

  наличие доставок, не выводит secret/JWT и даёт однозначный exit code для внешнего gate. Provider client и
  команда покрыты ещё тремя тестами; совместный набор диагностики и provider — `12 passed`. Реальный запуск

- полный связанный regression gate повторён на заново созданной тестовой схеме: `127 passed` для Git, Project

  GitHub принята с HTTP `202`;
- внешний webhook получил защитную границу для неожиданных ошибок: PPM пишет traceback только в серверный журнал,

  вернул HTTP `200`, а неподписанный webhook ожидаемо отклонён с HTTP `401`.
- выполнен контролируемый disconnect/purge/reconnect drill: API отключения вернул `204`, connection перешёл в
  `disconnected`, текущий snapshot получил `revoked`, а 241 производный code file был удалён;
- после purge сохранились 22 Git-объекта, историческая связь и обе Git-проекции Canvas; audit disconnect записан;
- повторное подключение через официальный project-scoped API вернуло `201`, connection снова `active`, а фоновая
