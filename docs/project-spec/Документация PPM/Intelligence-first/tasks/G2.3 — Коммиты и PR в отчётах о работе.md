# G2.3 — Коммиты и PR в отчётах о работе

## Пользовательский результат

Когда команда пишет отчёт о проделанной работе (документ Хранилища, страница или комментарий к задаче), она одной
кнопкой вставляет ссылку на коммит или PR своего проекта с его названием и статусом. PPM сам собирает сводку
«что сделано за неделю» по задачам и связанным с ними коммитам и PR.

## Основание

Замысел владельца 2026-09-28: «команда, когда пишет отчёт о проделанной работе, может ссылаться на коммиты». На
2026-09-28 в PPM нет отдельной сущности отчёта и нет вставки Git-объекта в текст. Коммит уже связывается с задачей по
ключу, а в текст можно вставить обычную ссылку.

## Зависимости

- G2.1 (провайдер Forgejo); G1.1/G1.2 — модели Git-объектов и автосвязь.

## Решение владельца (2026-09-29)

Владелец выбрал G2.3 в программу «ночь и день» («Коммиты в отчётах (G2.3)»), режим «делай до конца». Исследование
кода: `.superpowers/sdd/2026-09-29-g23-reports/research/g23-facts.md` — живого «чипа по id» в редакторе нет (mention
только для людей, embed задачи — мёртвая схема, новый узел требует правок и в схеме live-сервера); поиска по
Git-объектам нет (обзор «Кода» отдаёт первые 100 без фильтра); «задачи, сменившие статус за период, и их PR» уже
считает `ppm_canvas/changes.py` (для доски); заметки Хранилища — простое текстовое поле (markdown), страницы и
описания/комментарии задач — редактор `@plane/editor`.

**Выбор:** вставляется **обычная оформленная ссылка** (снимок на момент вставки), а не «живой» чип: работает во всех
редакторах, включая заметки Хранилища, переживает совместное редактирование и экспорт без правок live-сервера,
не раскрывает данные при просмотре (текст вставил человек с доступом — как ссылку вручную). Цена: статус в тексте
не обновляется сам — для отчёта это и нужно («как было на момент отчёта»).

## Scope

### A. API
- **G1. Поиск Git-объектов проекта:** `GET …/workspaces/<ws>/projects/<p>/git/objects/search/?q=&type=commit|pull_request&limit=`
  — по названию/сообщению, ветке, началу SHA (от 4 символов), номеру PR («#12» или «12»); свежие сверху; не больше
  20; право чтения «Кода» (`require_capability(…, "read")`), только объекты этого проекта; в ответе — поля
  `serialize_git_object` и готовая подпись для вставки.
- **G2. Сводка «Что сделано за период»:** `GET …/projects/<p>/git/work-summary/?from=&to=` (не длиннее 92 дней) —
  задачи проекта, сменившие статус за период (итоговый статус и группа: сделано/в работе/прочее), их коммиты и PR
  за период (с датой слияния), итоги (сколько задач сделано, коммитов, PR); право — как на чтение проекта; готовый
  текст в двух видах: markdown (для заметок Хранилища) и HTML (для страниц и описаний) — ссылки только на задачи и
  Git-объекты этого проекта.

### B. Web
- **G3. «Вставить коммит/PR»** — диалог: поиск (с задержкой ввода), фильтр «Коммиты / PR», выбор → вставка ссылки:
  коммит — «коммит a1b2c3d «Сообщение…»», PR — «PR #12 «Название» · Слит 28 сент.» (статус по-русски, дата
  слияния, если есть), ссылка — на Git-сервер/GitHub. Где: комментарий задачи и описание задачи (кнопка в панели
  редактора), страницы (пункт меню «/» и кнопка), заметки Хранилища (кнопка — вставка markdown в позицию курсора).
  Три действия: открыть, найти, выбрать. Проекта без подключённых репозиториев — понятная пустая подсказка.
- **G4. «Что сделано за период»** — диалог в страницах и заметках Хранилища: период (эта неделя, прошлая неделя,
  2 недели, месяц, свои даты), предпросмотр, «Вставить» → текст со ссылками в позицию курсора.
- **G5.** Строки по-русски, облик v1/v2, тесты в пределах базы.

### C. Проверка
- **G6.** API: поиск (виды запросов, лимит, чужой проект → 403/404 без утечки, гость без доступа к «Коду»), сводка
  (границы периода, часовой пояс проекта, задачи без Git, коммиты без задачи не попадают, ограничение 92 дня);
  web: подписи, вставка в каждом редакторе, markdown для Хранилища, диалоги. Сквозная проверка на стенде: вставка в
  комментарий и страницу, сводка за неделю совпадает с задачами и Git-объектами.

## Критерии приёмки

1. Ссылку на коммит или PR проекта можно вставить в документ и комментарий за три действия. Чужие проекты в поиске
   не видны.
2. Сводка за неделю совпадает с данными задач и Git-объектов проекта.
