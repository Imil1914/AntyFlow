# I1.1 — Vault backlinks, export и расширенные проекции

## Пользовательский результат

Project Vault работает как переносимая база знаний: wiki-links, backlinks, graph, versions/trash/export; Canvas поддерживает Plane Page, attachment и Vault file projections.

## Зависимости

- I0.7 — Vault foundation;
- AF0.5 — контракты Canvas projections;
- документы 07/09/16.

Зависимость от I0.10 удалена 2026-09-20: она создавала цикл
`I0.10 → AF1.2 → AF1.1 → I1.3 → I1.2 → I1.1 → I0.10`. Для этой карточки фактически нужны только
готовые Vault и projection foundations; единый внешний release gate остаётся более поздним этапом.

## Scope

- parse/resolve wiki-links;
- backlinks/graph API/UI;
- rename/move alias/update policy;
- versions/restore/trash;
- ZIP export manifest;
- Page/attachment/vault projections;
- previews/locators;
- explicit Page↔Markdown import/export provenance;
- expanded file type storage allowlist.

## Не входит

- automatic bidirectional Page sync;
- WebDAV/offline sync;
- office collaborative editing;
- OCR unless separate task approved.

## Порядок реализации

1. Добавить vault link model/migration.
2. Реализовать parser fixtures и resolver states.
3. Reindex links on Markdown version.
4. Реализовать rename/move stable ID behavior.
5. Добавить backlinks/graph UI.
6. Реализовать versions/restore/trash.
7. Реализовать deterministic export manifest/ZIP safeguards.
8. Добавить projection resolvers/renderers.
9. Реализовать explicit import/export provenance.
10. Выполнить Obsidian-open manual test exported folder.

## Критерии приёмки

1. Wiki-link даёт backlink/graph edge.
2. Rename/move не меняет entry ID и не теряет link.
3. Restore создаёт новую current version.
4. Export содержит обычную папочную структуру и `.md`.
5. ZIP безопасен и имеет manifest.
6. Page/file projections открывают canonical sources.
7. Удаление projection/source строго разделено.
8. Cross-project links не раскрывают source.

## Проверки

- parser/resolver ambiguity;
- rename/move/version conflicts;
- export traversal/symlink/large cases;
- projection permissions;
- Obsidian/manual Markdown readability;
- graph performance smoke;
- regression E5/E6.

## Rollback

Выключить expanded Vault features/node types. Canonical versions/links не удаляются.

## Реализация — 2026-09-20

- Добавлены project-scoped модели wiki-ссылок, alias старых путей и записей явного обмена с `Документами`.
- Wiki-link resolver поддерживает `[[Название]]`, alias/anchor, относительный приоритет внутри папки и состояния
  `resolved`, `missing`, `ambiguous`; ссылки переиндексируются при новой Markdown-версии, rename/move и restore.
- Rename/move сохраняют стабильный `entry_id`, защищены от циклического перемещения папок и поддерживают старые
  ссылки через alias.
- История версий и restore работают для Markdown и бинарных файлов; восстановление создаёт новую current version.
- Добавлена корзина с безопасным восстановлением и запретом редактирования для read-only роли.
- ZIP export формирует обычное дерево файлов и `ppm-vault-manifest.json`, не допускает traversal и ограничивает
  общий размер архива.
- Явные `Документ → Markdown` и `Markdown → Документ` операции сохраняют provenance версии и не включают
  автоматическую двустороннюю синхронизацию.
- В web UI добавлены вкладки `Материалы`, `Связи`, `Корзина`, история версий, backlinks, rename/move, ZIP export и
  понятный импорт/экспорт `Документов`.
- Page/attachment/Vault projections и разделение удаления projection/source повторно проверены в общем Canvas
  regression suite.

## Доказательства

- `19 passed` — контрактные тесты Project Vault, включая ambiguity, alias после rename/move, move-cycle,
  Markdown/binary restore, ZIP manifest/size limit, provenance и cross-project denial.

- `35 passed` — web-тесты; `25 passed` — пакет Canvas и browser-boundary audit.

- Авторизованный browser smoke подтвердил дерево, Markdown editor/preview, версии, карту связей, корзину и список
  документов текущего проекта в окне импорта.

## Известное состояние baseline

- Dev shell продолжает писать существующее предупреждение React hydration на уровне `app/root.tsx`, после чего
  восстанавливается client rendering. Production build успешен; предупреждение не возникло в коде I1.1 и остаётся
  отдельным общесистемным техническим долгом.

## Требуется owner review

1. Создать два Markdown с `[[wiki-link]]`, переименовать целевой материал и проверить backlink/карту связей.
2. Сохранить вторую версию и восстановить первую; убедиться, что появляется новая версия, а история не исчезает.
3. Переместить материал в корзину и восстановить.
4. Скачать ZIP и открыть экспортированную папку в Obsidian либо другом Markdown-клиенте.
5. Проверить явный импорт/экспорт `Документов` и отсутствие автоматической синхронизации.
