# I0.8 — Project Brain ingestion и изолированный индекс

## Пользовательский результат

Разрешённые Work Items, Vault Markdown и PDF превращаются в актуальный индекс конкретного project. Пользователь видит состояние индекса, ошибки и может безопасно повторить обработку.

## Зависимости

- I0.6 и I0.7;
- Brain/data/API/security документы 05/06/08/13;
- проверенный keyword-first backend без обязательного внешнего сервиса.

## Scope

- knowledge source/chunk/job models;
- common source adapter contract;
- Work Item, Markdown и PDF text adapters;
- source version/hash;
- worker queue/retry/idempotency;
- chunker с locators;
- Postgres full-text;
- project-scoped keyword retrieval с возможностью использовать уже имеющийся локальный индекс без зависимости от AI-провайдера;
- project/ACL filter;
- index states UI/API;
- deletion/access revocation exclusion;
- minimal reconciliation job.

## Не входит

- LLM answer UI;
- GraphRAG;
- OCR;
- office/code sources;
- reranker, если не доказан baseline;
- external connectors.

## Порядок реализации

1. Зафиксировать pipeline version и source schemas.
2. Добавить models/migrations/constraints.
3. Реализовать source adapters без browser content trust.
4. Реализовать normalized extraction и locators.
5. Реализовать deterministic chunking/hash.
6. Добавить keyword index.
7. Проверить поиск при отсутствии dense layer.
8. Реализовать job leases/retries/dead state.
9. Атомарно публиковать новую ready chunk set.
10. Немедленно исключать revoked/deleted sources.
11. Добавить project-filtered retrieval service без generation.
12. Создать fixture projects ROBOT/BIO и leakage tests.

## Критерии приёмки

1. Три source types становятся ready.
2. Повтор того же event/version не создаёт duplicate chunks.
3. Source update помечает stale и публикует новую version.
4. Source delete/revoke исключает его до async cleanup.
5. Retrieval всегда требует project scope.
6. Keyword retrieval работает без embeddings.
7. Chunk имеет locator и source version.
8. BIO marker не находится из ROBOT.
9. Ошибка parser/indexer не теряет source.

## Проверки

- adapter/chunker snapshots;
- idempotent jobs/retry;
- full-text Russian/exact identifier;
- поиск без dense layer;
- deletion/revoke;
- cross-project leakage;
- parser timeout/invalid PDF;
- worker restart/lease recovery;
- migration/build.

## Rollback

Выключить Brain flag/workers. Derived sources/chunks/vector data можно перестроить; canonical Plane/Vault data не меняется и не удаляется.

## Stop rules

- индексация пытается отправить данные наружу;
- filter применяется после global retrieval;
- индекс становится source of truth;
- parser работает без limits;
- keyword retrieval зависит от необязательного dense layer.

## Результат реализации 2026-09-20

Статус: `review`. Карточка реализована в `plane-fork`, но не переводится в `accepted` без решения владельца.

- добавлены project-scoped модели `PpmKnowledgeSource`, `PpmKnowledgeChunk`, `PpmIndexJob` и миграции;
- Work Item, Vault Markdown и PDF text layer проходят единый versioned adapter/chunker pipeline;
- новые chunks публикуются атомарно, прежняя версия снимается с публикации, удалённые и исключённые источники немедленно пропадают из retrieval;
- Celery выполняет idempotent jobs с lease, retry, dead/superseded states и периодической reconciliation;
- Postgres full-text использует русский и `simple` словари, exact-marker fallback остаётся доступен без embeddings;
- поиск и citations работают без настройки AI-провайдера; отсутствие dense layer не ломает keyword retrieval;
- retrieval фильтрует `workspace_id/project_id` до keyword/vector ranking и возвращает source version вместе с locator;
- на Холсте добавлена русская панель «Мозг проекта»: health, состояния источников, повторная индексация, поиск и переход к найденному источнику;
- `PPM_BRAIN_ENABLED=0` останавливает API/сигналы/workers Brain без изменения canonical Plane/Vault data.
