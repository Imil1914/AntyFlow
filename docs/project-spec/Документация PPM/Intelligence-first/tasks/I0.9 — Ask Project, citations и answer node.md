# I0.9 — Ask Project, citations и answer node

Решение владельца от 2026-09-23: генерация ответов и Answer-нода сняты
с текущего release gate вместе с AI-провайдерами. Уже реализованный
degraded/no-provider код и результаты проверок ниже сохранены как история.
Project-scoped поиск и citations остаются в активном объёме I0.8/I1.2.

## Пользовательский результат

Пользователь выделяет Canvas nodes либо спрашивает весь project, получает grounded ответ на русском с кликабельными источниками и сохраняет его как answer node.

## Зависимости

- I0.8;
- Canvas available I0.5/I0.6;
- configured completion provider либо explicit no-LLM degraded UI.

## Scope

- project query API;
- scope from selected nodes/bindings;
- keyword+dense rank fusion при доступности;
- source fetch and token budget;
- prompt separation;
- completion streaming/cancel;
- citation schema/validation;
- no-source/degraded behavior;
- agent run audit;
- `agent_query`/`agent_answer` nodes;
- golden RAG tests;
- no write actions.

## Не входит

- GraphRAG semantic edge bonus beyond direct selected bindings;
- autonomous agents;
- creating tasks/documents from answer;
- cross-project portfolio query;
- reranker unless already approved.

## Порядок реализации

1. Определить query/run/citation schemas.
2. Построить selected-node source scope server-side.
3. Реализовать retrieval fusion/diversity/token budget.
4. Fetch source text с повторным permission check.
5. Сформировать prompt sections `policy/user/sources`.
6. Реализовать streaming/cancel/timeouts.
7. Валидировать citations against provided source IDs.
8. Реализовать no-source и provider-failed fallbacks.
9. Создать query/answer node UI с source inspector.
10. Сохранить run metadata и answer binding.
11. Прогнать ROBOT/BIO/malicious fixtures.

## Критерии приёмки

1. Ответ по известному факту цитирует правильный source/locator.
2. Selected nodes ограничивают/приоритизируют контекст.
3. Неизвестный вопрос не вызывает выдуманную project citation.
4. Citation открывает Work Item/Markdown/PDF page.
5. Отменённый run не создаёт write actions.
6. Provider failure показывает retrieved sources либо ошибку без потери Canvas.
7. Malicious source не вызывает tool/action.
8. BIO data не появляется ROBOT user.

## Проверки

- retrieval/citation contract tests;
- streaming/cancel/timeout;
- golden questions;
- no-answer/conflicting sources;
- prompt injection;
- cross-project leakage;
- answer node reload;
- UI source navigation;
- web/worker build.

## Rollback

Выключить Brain query/answer node flag. Runs и answers остаются audit/history; canonical sources не менялись.

## Stop rules

- citations генерируются моделью без server validation;
- browser выбирает arbitrary source IDs без ACL;
- ответ автоматически создаёт/изменяет Work Item;
- provider secret передаётся browser;
- no-source ответ маскируется как подтверждённый факт.

## Реализовано 2026-09-20

- добавлен audit run для вопроса со статусами queue/retrieval/completion/terminal, идемпотентностью, отменой и диагностикой;
- scope выбранных Canvas nodes вычисляется только на server по active bindings, а source IDs из browser не принимаются;
- retrieval использует project-scoped keyword/hybrid pipeline I0.8, ограничение до 24 chunks и 6000 context tokens;
- повторная проверка workspace/project выполняется при загрузке полного текста источника;
- completion provider изолирован server-side, prompt разделяет policy/user/untrusted sources, citations проходят server validation;
- без настроенного provider показывается явная проверяемая сводка, при отсутствии подтверждений — `no_sources` без выдуманных ссылок;
- реализованы POST/GET/cancel/SSE endpoints и polling fallback в web;
- на холсте доступны русская панель «Спросить проект», поиск источников, selected context, отмена, кликабельные citations и явное сохранение пары `agent_query`/`agent_answer`;
- ссылки Work Item и Vault формируются сервером и открывают canonical source;
- добавлены ROBOT/BIO isolation, malicious source, invalid citation, provider failure, cancellation и stream contract fixtures;
- внешний completion по умолчанию выключен и требует отдельного разрешения `PPM_BRAIN_ALLOW_EXTERNAL_COMPLETIONS`.

## Дополнение 2026-09-22 — восстановление после reload

- project-scoped `GET .../answers/` возвращает до 50 последних собственных запусков, но не раскрывает ответы
  другого пользователя того же проекта;
- при открытии панели PPM сравнивает последние Answer и Project Agent runs, приоритетно выбирает самый свежий
  активный процесс и не показывает поверх него устаревший terminal-результат другого типа;
- активный Answer run снова подключается к существующему SSE events endpoint с polling fallback; UI показывает
  «Наблюдение за ответом восстановлено» и оставляет доступной безопасную остановку;
- terminal-снимок снимает recovery-состояние, а после следующего reload остаётся выбранным как самый свежий
  результат без возврата к старой карточке агента;
- живой E2E создал контролируемый `queued` Answer run, прошёл reload → восстановление → stop → reload и показал
  «Запрос остановлен» без изменений задач, Хранилища или Холста;
- полный Project Brain suite: 55 тестов; web suite: 48 тестов, TypeScript, Oxfmt, Oxlint и production build
  пройдены.

## Требуется owner review

1. Спросить проект о факте из Work Item и открыть citation.
2. Спросить о факте из Markdown/PDF и открыть соответствующий материал.
3. Выделить один связанный объект и убедиться, что ответ не использует остальные источники.
4. Задать неизвестный вопрос и проверить честное состояние «Нет данных».
5. Сохранить ответ на холсте, обновить страницу и проверить сохранение обеих нод.
6. Решить, подключать ли внешний completion provider; безопасная сводка по источникам уже работает без него.
