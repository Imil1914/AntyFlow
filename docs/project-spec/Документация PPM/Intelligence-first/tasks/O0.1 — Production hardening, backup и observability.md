# O0.1 — Production hardening, backup и observability

## Пользовательский результат

PPM разворачивается воспроизводимо, сообщает о деградации до потери данных и восстанавливается из проверенной
резервной копии.

## Зависимости и входы

- AF1.2 accepted;
- G1.3 accepted;
- I0.10 review-ready;
- документ 14.

## Scope

- production-like manifests и migration runbook;
- health/readiness для DB, storage, queues, realtime, Brain и Git sync;
- logs/metrics/traces/alerts без secrets;
- backup/restore DB, Vault objects и integration metadata;
- secret rotation и incident runbooks;
- rate limits, security headers и dependency/license scan;
- capacity/performance test;
- disaster recovery rehearsal.

## Не входит

- обещание SLA без измерений;
- backup внешних Git repositories вместо provider;

## Критерии приёмки

1. Чистое окружение поднимается из документированных manifests.
2. Backup восстановлен в отдельном окружении и проверен сквозным сценарием.
3. Отказ одной зависимости отражается понятным health/degraded state.
4. Logs и traces не содержат токены, секреты и содержимое private files.
5. Утверждённые performance budgets выполняются на контрольном наборе.

## Проверки

- clean deploy и migration;
- backup/restore drill;
- dependency failure injection;
- secret/log scan;
- load/capacity;
- security headers/rate limits.

## Rollback

Вернуться к последнему проверенному deployment manifest; schema/data rollback следует отдельному migration runbook.
